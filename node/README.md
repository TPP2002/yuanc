# 出口小主机节点程序

这份程序装在出口小主机上，提供两条加密通道，让配对过的电脑经这台主机的宽带上网：主通道 VLESS + Reality 走 TCP 443，备用通道 Hysteria2 走 UDP 24443 并加混淆。另有自用设备管理、邀请码模式的名单同步、看门狗、救援单元、客户端包托管和更新。

2026-11-27 在客户寄来的软路由（Debian 12.15）上装好并实测：自用配对和邀请码两种方式都能连通，出口是这台主机所在宽带的公网地址。入口端口映射和更新还没在真机上测。过程与结论见《[节点真机验收-2026-11-27](../docs/acceptance/节点真机验收-2026-11-27.md)》。

## 首次使用

系统用 Debian 12 或 Ubuntu 24.04，Python 3.11 或更新版本。不要先在正在提供服务的机器上尝试安装。程序不自动安装系统工具，也不自动下载内核。

1. 装系统工具：`sudo apt-get install python3-cryptography curl nftables miniupnpc qrencode`。系统自带的 nftables 服务保持关闭即可，程序只管自己的 `table inet exitnode`。
2. 装隧道内核：sing-box 1.13.21 的官方 linux-amd64 包，核对哈希后放到 `/usr/bin/sing-box`。`init` 会把它复制进版本目录，以后由更新器管理。
3. 把仓库的 `node/` 目录拷到小主机，例如 `/home/ops/yuanc/node`。
4. 把 `examples/config.example.toml` 复制成 `/etc/exitnode/config.toml` 并填写，方法见 [配置说明](../docs/node/配置说明.md)。示例里 `binary = "/usr/bin/sing-box"` 这一行要删掉，否则隧道服务一直用这个路径的内核，以后更新内核不生效。
5. 安装：`cd / && sudo env PYTHONPATH=/home/ops/yuanc/node python3 -P -m exitnode init`。装完会导出第一台电脑的配对文件。

装好以后程序在 `/opt/exitnode/current`，之后的命令都写成 `cd / && sudo env PYTHONPATH=/opt/exitnode/current python3 -P -m exitnode <命令>`，下文简写成 `exitnode <命令>`。`cd /` 和 `-P` 让 Python 不从当前目录加载同名模块。

Windows 只用于开发和模拟测试，真实系统操作只支持 Linux。

不要把密码、令牌、设备身份或密钥写进配置文件。凭据只放在 `/var/lib/exitnode/secrets/`，不要把这个目录打包给别人。

## 七项操作

| 操作 | 命令 | 会发生什么 |
| --- | --- | --- |
| 安装 | `exitnode init` | 建目录、生成凭据、写服务与网络规则并当场启动，导出第一台电脑的配对文件；重复跑会跳过已完成的步骤 |
| 检查 | `exitnode check` | 按顺序显示网卡、上游、入口、代理、真实出口和各服务的检查结果 |
| 状态 | `exitnode status` | 显示正常、重连中、需重新授权或需人工处理，以及经哪条通道能上网 |
| 导出诊断 | `exitnode diagnose --output /tmp/exitnode-diagnose.zip` | 导出配置、检查结果、版本和本项目各服务最近的系统日志，自动打码凭据 |
| 更新 | `exitnode upgrade` | 检查并安装新版本，健康检查不过自动切回原版本，见 [更新与回退说明](../docs/node/更新与回退说明.md) |
| 撤回 | `exitnode rollback` | 按安装记录倒序撤回；一项失败仍继续处理其他项 |
| 卸载 | `exitnode uninstall` | 撤回组件并清除安装清单，保留凭据和其他仍存在的数据 |

使用其他配置位置时，加 `--config /绝对路径/config.toml`。检查和状态命令可加 `--json`，供其他程序读取。另有 `device`（自用设备的添加、导出、吊销）、`watchdog`、`authsync`、`publisher`、`rescue`、`winclient`、`admin` 几组子命令，说明在 `docs/node/` 下对应的文档里。

## 怎样理解结果

`check` 的入口、代理、真实出口三层是真结果：入口看两个端口是否在监听；代理与出口用第一台没吊销的设备，经本机两个入口各取一次 `https://1.1.1.1/cdn-cgi/trace`，核对出口地址和地区。还没有可用设备，或网络、上游不通时，代理与出口两层显示「跳过」，不冒充通过。一条通道等不到结果最多等 15 秒，平时一次检查约 0.5 秒。

`status` 显示「正常」时，原因一句写明经哪条通道能上网；一条通道不通会点名是哪条。

多个上游目标中有一个可连接就不判定上游中断，不会因为某一个网站打不开就重启主机。隧道服务停了，看门狗约 4 分钟内重启它；程序文件坏了，救援单元约 10 分钟内装回出厂版本。详见 [看门狗说明](../docs/node/看门狗说明.md)、[救援单元说明](../docs/node/救援单元说明.md)。

## 安装中断和撤回

默认记录位于 `/var/lib/exitnode/manifest.json`。请保留它：重复安装会跳过完成的步骤，中断后会继续未完成步骤。不要手工删除记录后再次安装，否则程序无法确认已有服务和规则是否属于本次安装。

撤回失败时会列出失败项，排除权限或系统工具问题后可再次撤回。`rollback --to-step 步骤名` 会保留指定步骤及之前的步骤。原有同名服务或网络规则不在清单里时，安装会停止，让维护人员核对，不会擅自覆盖。

普通卸载保留凭据。只有确定永久弃用节点时，才使用 `uninstall --purge` 删除整个凭据目录；该操作无法恢复。其他未清空的目录会保留，不递归删除用户文件。
