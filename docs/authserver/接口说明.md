# 邀请码鉴权服务接口说明

本服务管理邀请码、账号期限、设备授权和节点放行名单。应用只提供 HTTP；对外 HTTPS 由反向代理或 uvicorn 的 TLS 参数负责。管理接口应按设计正本放在隧道内或受访问白名单保护，本包不修改网络规则。

## 启动与配置

包位于 `authserver/authserver/`，配置示例为 `authserver/examples/config.example.toml`。示例所有值都是占位符，不能直接启动：数字字段须替换成不带引号的整数。`security.admin_key`、`security.node_key`、`security.token_salt` 都必须显式提供，不能为空或保留占位符。三个值应分别生成，保存在仓库外的配置文件中。服务器盐必须备份；更换它会使现有令牌以及派生的节点密码失效。

配置分为四节：

| 节 | 字段 | 说明 |
|---|---|---|
| server | bind、port | 服务监听地址和端口；启动 uvicorn 时用对应的 `--host`、`--port` 参数 |
| security | admin_key、node_key、token_salt | 管理员密钥、独立节点密钥、令牌哈希与设备密码派生用盐；无默认密钥 |
| node | host、reality_port、hy2_port、reality_public_key、short_id、sni、hy2_server_name、hy2_certificate_path、hy2_obfs_password_path | 下发给获准设备的节点连接参数；`hy2_obfs_password_path` 可选，指向节点 `/var/lib/exitnode/secrets/hy2.obfs` 的本地副本，留空表示节点未启用备用通道混淆，填了但读不到或格式不对（须为 16～128 个字母、数字、`-`、`_`）则拒绝启动；更新副本后须重启 |
| limits | session_hours、default_device_limit、redeem_per_ip_per_hour | 可省略，默认分别为 6、2、10 |
| node（可选环境字段） | time_zone、country | 节点所在城市时区与两位大写国家码，默认空串；非空随会话用于客户端时区设置与国家自检，详见「会话与客户端配置」 |

`AUTHSERVER_CONFIG` 指定配置文件，`AUTHSERVER_DB` 指定 SQLite 文件（省略则为当前目录的 `authserver.sqlite3`）。部署时显式设置数据库路径，将目录权限仅授予服务账号；数据库路径的父目录须预先存在。

在仓库根目录、已有依赖的解释器中，可用以下形式启动。路径及监听参数由部署方替换，下面的回环地址适合前置本机 HTTPS 反向代理：

```powershell
$env:AUTHSERVER_CONFIG = 'C:/部署目录/config.toml'
$env:AUTHSERVER_DB = 'C:/部署目录/authserver.sqlite3'
python -m uvicorn authserver.app:create_app --factory --app-dir authserver --host 127.0.0.1 --port 8000 --workers 1 --no-server-header
```

监听参数应与 `server` 节保持一致，应用工厂不自行开启监听端口。反向代理须正确配置 uvicorn 的可信代理地址；应用只使用 ASGI 的客户端 IP，不自行相信任意 `X-Forwarded-For` 请求头。兑换与会话限速是单进程内存计数，因此此版本使用一个 worker；进程重启会清空计数。

应用工厂也支持 `create_app(settings, db_path, clock)` 注入配置、数据库路径和服务器时钟，便于隔离测试。所有持久化时间均为 UTC ISO 8601，过期判断使用服务器时间且到期瞬间即拒绝。

## 对外表现与证书指纹

接口文档页已关闭，`/docs`、`/redoc`、`/openapi.json` 不再提供文档。未知路径、错误方法、管理与节点接口缺少密钥或密钥不对时，都返回同一张通用 404 网页，状态码、Content-Type 和正文逐字节相同。启动参数 `--no-server-header` 去掉响应头里的 `server: uvicorn`。

客户端接口对路径、方法和格式正确的请求仍返回原有 JSON 状态，包括令牌无效、邀请码不存在等业务错误；参数无效仍返回原有 422 JSON。管理与节点接口密钥正确时行为不变。下文接口表中管理与节点密钥错误的原 401 描述，以本节的通用 404 网页为准；客户端业务状态不变。已知局限：有人照着接口格式发请求，仍能认出这是本服务。首次登录走隧道属于后续方案，本次未做。

分发版客户端通过 `https://<鉴权服务器IPv4>:<端口>` 直连。HTTPS 证书可以用自签证书，不再需要给 IP 签发的公共证书。客户端只靠 `server.json` 中的 `server_spki_sha256` 认证书公钥：指纹一致时忽略证书链和主机名错误；指纹不一致时，即使系统证书校验通过也拒绝连接。

用部署证书计算公钥指纹（将 `<证书.pem>` 替换为证书路径）：

```sh
openssl x509 -in <证书.pem> -pubkey -noout | openssl pkey -pubin -outform der | openssl dgst -sha256 -binary | openssl base64 -A
```

结果是 44 个字符、以 `=` 结尾的 base64，将完整结果写入 `server_spki_sha256`。换证书但不换私钥时指纹不变；换私钥必须同时给所有客户端发新的 `server.json`。

真机待验证（本次未执行）：用 `curl -k` 分别访问 `https://<鉴权服务器IPv4>:<端口>/`、`/docs`、`/admin/accounts`（不带管理密钥），确认都得到同一张 404 网页，且响应头没有 `server: uvicorn`。自动测试通过不能替代该项部署验证。

## 接口表

成功响应均为 JSON，状态码 200，附 `Cache-Control: no-store`。错误响应统一为 `{"detail":"中文说明"}`，参数错误不会回显含令牌的输入内容。

| 方法与路径 | 谁调用／认证 | 请求或结果 | 主要错误 |
|---|---|---|---|
| POST `/admin/invites` | 管理员，`X-Admin-Key` | `{days,max_uses:1,note:""}` → 邀请码及期限、次数 | 401、422 |
| GET `/admin/accounts` | 管理员，`X-Admin-Key` | 账号数组 | 401 |
| GET `/admin/accounts/{id}` | 管理员，`X-Admin-Key` | 账号及设备摘要 | 401、404 |
| POST `/admin/accounts/{id}/extend` | 管理员，`X-Admin-Key` | `{days}`，在原到期日上叠加天数 | 401、404、422 |
| POST `/admin/accounts/{id}/disable` | 管理员，`X-Admin-Key` | 停用账号并清除已发会话 | 401、404 |
| POST `/admin/accounts/{id}/enable` | 管理员，`X-Admin-Key` | 恢复账号状态，不改变到期日、不解除设备吊销 | 401、404 |
| GET `/admin/devices` | 管理员，`X-Admin-Key` | 设备摘要数组，不返回令牌哈希或节点凭据 | 401 |
| POST `/admin/devices/{id}/revoke` | 管理员，`X-Admin-Key` | 写入吊销时间，清除会话，不删设备行 | 401、404 |
| GET `/admin/audit` | 管理员，`X-Admin-Key` | 按编号排序的审计记录 | 401 |
| POST `/client/redeem` | 客户端，邀请码；续期还带刷新令牌 | 见下文 | 401、403、404、409、410、422、423、429 |
| POST `/client/session` | 客户端，请求体中的刷新令牌 | `{refresh_token}` → 会话、节点凭据及客户端配置 | 401、403、409、410、422、423、429 |
| POST `/client/logout` | 客户端，请求体中的一种令牌 | `{refresh_token}` 或 `{session_token}`，二选一 | 401、403、409、410、422、423 |
| GET `/node/allowed` | 节点，`X-Node-Key` | `{version,allowed:[]}` | 401 |
| POST `/node/heartbeat` | 节点，`X-Node-Key` | 无必填请求体，保存接收时间及来源 IP → `{at}` | 401 |

错误码含义：

| 状态码 | 含义与客户端处理 |
|---|---|
| 401 | 密钥或令牌缺失／无效，或会话过期；提示重新登录，不用原令牌无限重试 |
| 403 | 账号停用；提示联系管理员 |
| 404 | 邀请码不存在，或指定管理对象不存在 |
| 409 | 设备数达到／超过上限，或邀请码次数用完；`detail` 分别明确指出“设备”或“邀请码使用次数” |
| 410 | 账号到期；提示兑换新码续期 |
| 422 | 字段缺失、类型或取值不合法、期限超出日期支持范围 |
| 423 | 设备已吊销；提示联系管理员 |
| 429 | 同一 IP 一小时内该类接口请求过多；附 `Retry-After: 3600`，停止立即重试 |

兑换和换会话各自按 IP 使用一个滚动一小时窗口，共用配置中的上限数值；成功及业务拒绝的请求都计数。管理员、节点接口不占这两个计数器。

## 兑换、续期与设备

兑换请求：

```json
{
  "code": "<管理员发的邀请码>",
  "device": {
    "platform": "windows",
    "name": "我的电脑",
    "fingerprint": "<客户端稳定保存的设备指纹>"
  }
}
```

响应含 `account_id`、`expires_at`、`refresh_token`、`device_id`。首次兑换建号，到期日为兑换时刻加邀请码天数。邀请码次数不足固定返回 **409**，不存在固定返回 **404**。天数和次数都必须为正整数，支持 1、7、30 及其他天数。

已有账号续期时，请在同一请求中增加 `refresh_token`。期限叠加到账号原到期日，不改成“今天加天数”；即使账号已经到期，也能凭未吊销设备的有效刷新令牌兑换新码。过期账号的换会话仍然拒绝。停用账号、已吊销设备不能通过兑换绕过限制。

在新设备上使用已有账号的刷新令牌和一个可用新码，会向该账号绑定新设备，同时叠加本次邀请码期限。达到设备上限时整笔事务回滚：不消耗邀请码、不延长期限、不创建设备。默认上限为两台未吊销设备。

同一码和同一设备指纹重复兑换不会重复建号、占设备数或扣次数。续期重试也不会叠加两遍期限。初次兑换重试由于数据库不保留原文令牌，会重新发一个刷新令牌并使该设备旧令牌、旧会话失效；客户端应保存最后一次成功响应。带本设备有效刷新令牌的续期重试保留该令牌。邀请码及设备指纹的组合可用于首次兑换重试，应避免外泄。

退出登录会清除本设备刷新令牌哈希和全部会话，并从下次节点名单中移除该设备；设备记录保留。吊销同样保留设备行和最初吊销时间，后续凭原刷新令牌换会话返回 423。

## 会话与客户端配置

`/client/session` 返回：

```json
{
  "session_token": "<会话令牌>",
  "session_expires_at": "<UTC时间>",
  "account_expires_at": "<UTC时间>",
  "node": {
    "host": "<节点地址>",
    "reality_port": 443,
    "hy2_port": 24443,
    "sni": "<域名>",
    "reality_public_key": "<公钥>",
    "short_id": "<短标识>",
    "uuid": "<本设备标识>",
    "hy2_password": "<本设备备用通道密码>",
    "hy2_server_name": "exitnode",
    "hy2_certificate": ["<备用通道证书逐行文本>"],
    "hy2_obfs_password": "<节点级备用通道混淆密码，未配置时为空串>",
    "time_zone": "<节点所在城市的时区，未配置时为空串>",
    "country": "<两位大写国家码，未配置时为空串>"
  }
}
```

`node.time_zone` 与 `node.country` 是可选配置，均默认为空串；会话响应仍返回这两个键。`time_zone` 非空时须全匹配 `[A-Za-z0-9 ._+/()-]{1,64}`，可填节点所在城市的 IANA 时区名（如 `Australia/Sydney`）或 Windows 时区 ID；`country` 非空时须全匹配 `[A-Z]{2}`，如 `AU`。它们只用于客户端环境策略与出口国家自检，不改变客户端本地渲染的连接配置。

客户端按节点非空值、本机 `environment.json`、默认值的顺序选择；无法识别的时区回落本机配置，不影响国家码。旧服务未返回字段时客户端照常使用本机配置；续期只改变时区时只恢复并重套用环境，不重启隧道。语言列表仍由客户端本机配置决定。

`node.hy2_obfs_password` 是节点级的一个值（所有设备相同），来自 `node.hy2_obfs_password_path` 指向的副本；
未配置路径时为空串 `""`（字段仍然存在）。混淆密码按凭据对待，
不写日志与审计。节点再次运行 `exitnode init` 启用混淆后，须把新生成的 `hy2.obfs` 同步到鉴权服务器并重启，
否则下发的会话仍不带混淆，备用通道连不上。

### 连接配置不再下发

客户端（自用与分发两种模式）按 `node` 的 11 个连接字段本地渲染，口径正本为 `node/exitnode/proxy/client_config.py`，由黄金文件 `node/tests/golden/proxy/client-windows.json` 锁住。旧版服务仍返回的 `singbox_config`，客户端一律忽略。这样鉴权服务被攻破也不能通过下发连接配置，给客户端塞入带直连出站的配置。

会话默认六小时失效；服务在验证会话时也重新检查账号和设备，账号先到期时不会等满六小时才拒绝。刷新令牌只存 `sha256(token_salt + raw)`，会话令牌同样处理。设备备用通道密码以服务器盐和设备 UUID 作带域分隔的 HMAC 派生，不将明文密码存入数据库。管理员与节点密钥仅从配置读取，不写入数据库。

自动测试检查客户端本地渲染和服务行为，不代表已经完成客户端内核加载、真实隧道连通或设备断网保护验证。

## 节点名单与审计

名单严格按并行节点单的形状输出，不导入节点包：

```json
{
  "version": "<名单内容摘要>",
  "allowed": [
    {
      "uuid": "<设备标识>",
      "hy2_password": "<备用通道密码>",
      "account_id": "<账号编号>",
      "device_id": "<设备编号>"
    }
  ]
}
```

只列未到期、未停用、未吊销且仍持有刷新授权的设备。`version` 是当前有序名单的 SHA-256 内容摘要；账号自然到期即会改变名单和版本，不依赖后台定时写库。节点按设计的 60 秒周期拉取并应用名单，实际节点应用由节点单负责。

心跳表保留最近一次心跳，审计表保留每次心跳。所有成功业务写操作及其审计在同一事务中提交；审计记录 `who`、`what`、`at`、`ip`，包括管理员操作、设备兑换、换会话、退出与节点心跳。审计不写请求体、刷新令牌、会话令牌或节点密码。业务失败回滚全部改动。审计中的邀请码原文属于允许保留的可分发资料。

## 离线管理员命令

管理员可直接访问同一数据库，不必先启动接口服务。配置文件与数据库路径必须与服务一致；离线操作的审计来源为 `local`。在仓库根目录先令 Python 能找到包：

```powershell
$env:PYTHONPATH = 'authserver'
# AUTHSERVER_CONFIG 和 AUTHSERVER_DB 按前文设置，不能指向仓库内凭据。
python -m authserver.admin_cli invite --days 30 --uses 1 --note '给朋友使用'
python -m authserver.admin_cli accounts
python -m authserver.admin_cli devices
python -m authserver.admin_cli revoke '<设备编号>'
python -m authserver.admin_cli extend '<账号编号>' --days 7
```

也支持将 `--config <文件>`、`--db <文件>` 放在子命令之前。包的安装元数据声明了等价的 `authserver-admin` 入口；本施工工位没有执行安装。命令输出为 JSON，参数或配置错误以非零状态退出。

## 邀请码怎么发、怎么停人

管理员先选择给对方用几天、这个码最多给几个人用，再生成邀请码，把码私下发给对方。对方在软件里填码就能开通，从兑换当天开始计算期限。续费不在这里办理；要延长使用时间，就发一个新码让对方续期，或由管理员直接延期。想暂停某个人，就找到他的账号并停用；只想停某台电脑，就找到那台设备并吊销。到期后也会自动停止放行，节点按同步周期执行。
