# 节点真机验收记录（2026-11-27）

节点程序 0.1.0 装在客户寄来的软路由上，六个维护命令都在真机跑过。自用模式和邀请码模式都连上了，出口是负责人家里宽带的公网地址，地区 AU。口径速查表和各说明文档里节点、鉴权服务的「真机待验证」项，本次实测了大部分，结论逐条写在下面；没测的写了原因。实测中发现三处程序问题，已派单修复（见「发现的问题」）。

整套 Windows 客户端的真机验收不在本记录，归看板卡 WINCLIENT-REALMACHINE-ACCEPT-1022。本记录里的「电脑端」是开发机上的 sing-box 1.13.21 Windows 版，出站写法与客户端本地渲染的一致（`node/exitnode/proxy/client_config.py`），入站换成本机三个代理端口：一个走自动选择，一个只走主通道，一个只走备用通道。

## 装法

1. 装系统依赖：`apt-get install python3-cryptography curl nftables miniupnpc qrencode tcpdump python3-venv openssl rsync`。系统自带的 nftables 服务保持关闭，规则集为空，装完只有本项目自己的 `table inet exitnode`。
2. 内核：开发机上的官方发布包经 SSH 拷过去，核对两个哈希后装到 `/usr/bin/sing-box`；`init` 再把它复制进版本目录 `/opt/exitnode/releases/0.1.0/bin/`，隧道服务用的是版本目录里那份。
3. 代码：开发机把 `node/` 与 `authserver/` 打包，经 SSH 同步到 `/home/ops/yuanc`，不经 GitHub。
4. 配置：从 `node/examples/config.example.toml` 复制，改四处：节点名称；`publisher.mode` 改成 `relay`（本次不做路由器端口映射）；动态域名两项填「不使用」；删掉 `binary` 一行，让检查与运行都用版本目录里的内核。
5. 伪装站点：在节点上实测 `www.abc.net.au` 支持 TLS 1.3 与 HTTP/2（ALPN h2，证书校验通过，HTTP/2 返回 200，用时 0.28 秒），沿用示例值。
6. 安装：`cd / && sudo env PYTHONPATH=/home/ops/yuanc/node python3 -P -m exitnode init`，失败项为无，自动导出「第一台电脑」配对文件并打印二维码。之后的维护命令都用 `cd / && sudo env PYTHONPATH=/opt/exitnode/current python3 -P -m exitnode <命令>`。

## 发现的问题

1. **检查三层是占位**：`check` 的入口可达、代理进程、真实出口三层一直是「未接入」，`status` 永远说尚不能确认可上网，维护人员看不出节点能不能上网。真机上验证了自测办法：用 `sing-box tools fetch` 经节点自己的两个入口取 `https://1.1.1.1/cdn-cgi/trace`，主通道 0.31 秒、备用通道 0.11 秒拿到出口地址与地区。已修（PR #81），复测见下节。
2. **装完不当场启动规则单元与托管服务**：`init` 对这两个单元只设了开机启动，装完到第一次重启之间，「服务加固」「客户端托管服务」两层都是失败，隧道里也拿不到客户端包。已修（PR #81）。
3. **诊断包没有日志**：程序不写自己的日志文件，各服务的输出都在 systemd 日志里，诊断包的「最近日志」只有「暂无日志」。已修（PR #81），改为附上本项目各单元最近 300 行系统日志（打码后）。
4. **托管服务能被半开连接占满**：并发上限 32、每条连接最长等 15 秒，经隧道的任何一台设备只要占住 32 条连接，其他设备就下载不了客户端包。另立卡处理。
5. **救援单元在时间拨回后约一天不动作**：救援判断「是否进入新一轮」用的计数时刻在拨快期间被写成了未来时间，拨回后没有剔除，接下来约一天里各项失败计数都不涨，程序坏了、配置坏了、隧道服务失败都不处理。已修（PR #84），复测见「修复后复测」。

## 修复后复测（PR #81，22:46~22:50）

主干代码经 SSH 同步到节点，先用旧程序 `rollback`，再用新代码 `init`：

- `init` 失败项为无；装完立刻 `check`，十一层全部通过，退出值 0。入口层「主入口 TCP 443 与备用入口 UDP 24443 都在监听」；代理层「主通道与备用通道自测都能连通」；出口层「经隧道出口 <家里宽带地址>，地区 AU」；「服务加固」「客户端托管服务」两层当场通过。
- `status`：「正常：检查通过，经隧道可以上网」。
- 临时加一张测试规则表挡住 UDP 24443（查完即删）：代理层「主通道能连通；备用通道自测不通，请检查 UDP 24443」，`status`「检查通过，经主通道可以上网；备用通道自测不通」。这时一次检查约 15 秒（备用通道等满超时）。
- `diagnose`：「最近日志」分「程序日志」「系统日志」两段，系统日志 300 行。诊断包里的检查结果只有 6 层，缺看门狗、救援、服务加固、名单同步、托管服务 5 层，另立卡。
- 自测用的临时配置文件查完即删，凭据目录里没有残留。

救援时间回拨修复（PR #84，23:13~23:24）：装上新代码时，救援状态里的计数时刻还停在 11-28 22:06。新代码跑第一轮就记 `clock_adjusted`，计数时刻改回当前时间。随后停掉看门狗定时器、让隧道服务进入失败状态，救援连数两轮（23:18、23:23），23:23:45 解除失败并重启，失败后 570 秒恢复；看门狗定时器已还原。

开发期同版本换代码要多两步：`init` 不覆盖同版本号、内容不同的程序目录，要先删 `/opt/exitnode/releases/0.1.0` 和 `current` 链接；救援的出厂包 `/opt/exitnode-rescue/factory` 也要删掉让 `init` 重新复制。`init` 这时报「已有救援包内容不同……更新代码请用 rescue refresh」，但 `rescue refresh` 只更新救援程序、不更新出厂包，照提示做了仍装不上。升级后一天内（出厂包还没被提升）重跑 `init` 也会碰到，另立卡。
