## 1. 一句话

客户的 Windows 电脑在中国大陆,点一下客户端,所有上网流量经加密隧道到澳洲家里那台小主机,再从澳洲宽带出去;外面看到的是澳洲家庭 IP。小主机自己装、自己修、自己升级;客户在管理后台建用户、发凭据、停用户。

## 2. 交接文档里要改口径的地方(A 类冲突,逐条给选项)

交接文档写的是「同一局域网或一般互联网环境下的出口节点」,没考虑客户端在中国大陆这一条。它改变三件事:

| 编号 | 交接文档原口径 | 为什么在「中国 → 澳洲」下不成立 | 选项 |
|---|---|---|---|
| A-1 | WireGuard 与 Tailscale 均为候选,首期用成熟客户端 | 中国出境链路上的审查设备对 WireGuard/OpenVPN/IPsec 握手特征识别成熟,常见结果是限速或直接掐断;Tailscale 的协调服务器与中继在境内可达性不稳定,且底层仍是 WireGuard | ①改用 sing-box 系协议(§3,推荐);②坚持 WireGuard,接受「随时可能不通」;③Tailscale 自建中继,仍受 WireGuard 特征影响 |
| A-2 | 优先不依赖手工端口转发;接到另一台路由自动恢复 | 节点在澳洲家庭路由后面,客户端要从中国主动连进去,**必须有一个入站入口**;「零端口转发」只有 NAT 穿透(境内不稳)或外部中继(要花钱)两条路 | §4 的 A/B 两案 |
| A-3 | 首期用现成客户端 | 负责人确认交付物是 Windows 一键 .exe,现成客户端只当安卓过渡方案 | 按 §6 做自研 Windows 客户端;安卓用官方 sing-box 应用导入订阅,延期 |
| A-4 | 设备授权、撤销、凭据更新 | 客户追加「账户与权限体系」,疑似多人分发 | §5;用途须客户书面确认 |

交接文档其余条款(幂等安装、自愈、A/B 更新、只管自己的规则、凭据不入库、A01~A12 验收)**全部保留**,在 §9 对应。

## 3. 隧道协议(待拍板,推荐方案已写死参数)

**名词先翻成人话。**
- **TUN 模式**:客户端在电脑上造一张「虚拟网卡」,系统把所有程序的流量都塞进这张网卡,客户端再把它们加密发给澳洲节点。对比「代理模式」只管浏览器这类认系统代理的程序,TUN 模式是真正的「一键全局」,也是能做「隧道断了就断网、不漏流量」的前提。客户要的「TUN 隧道」就是这个。
- **Reality**:一种让隧道流量看起来像「在正常访问某个真实国外网站」的伪装手法,审查设备很难把它和普通 HTTPS 区分开。
- **Hysteria2**:基于 UDP 的隧道协议,弱网下比 TCP 快,但 UDP 在境内更容易被限速,所以只当备胎。

**推荐:节点与客户端都用 sing-box 内核。**
- 主通道:VLESS + Reality,TCP 443 端口,伪装目标选一个澳洲本地的大站。
- 备通道:Hysteria2,UDP 端口随机高位;客户端主通道连不上自动切备通道,两条都不通就报「需人工处理」,**不回落到裸网**。
- 每台设备一个独立 UUID,撤销就是从节点配置里删掉并热重载。
- DNS:客户端 TUN 接管系统 DNS,全部走隧道到节点解析;IPv6 在客户端侧阻断(节点侧澳洲宽带 IPv6 情况现场核查后再决定是否放行)。

为什么不用 WireGuard:见 A-1。为什么不用 Tailscale:它解决的是「两台机器找到彼此」,解决不了「握手被识别」;而且账号在第三方手里。

## 4. 节点可达性:客户端怎么找到澳洲家里那台机器(待拍板)

| | 方案 A:节点自己开门 + 动态域名 | 方案 B:一台便宜 VPS 当中继与会合点 |
|---|---|---|
| 做法 | 节点启动后用 UPnP/NAT-PMP 向澳洲家用路由申请端口映射,把当前公网 IP 和端口写到一个域名(DDNS);客户端连域名 | 节点主动向外连一台 VPS(香港/新加坡/日本),客户端连 VPS,VPS 把流量转到澳洲节点再出去 |
| 需要客户做什么 | 有一个域名(年费几十元)或用免费动态域名;**路由器 UPnP 关着就要在路由器上手动开一次端口转发**(换路由器要重做一次,与交接文档 A06 冲突) | 每月约 5 美元 VPS;不碰澳洲路由器,换路由器零操作 |
| 国内连接质量 | 国内直连澳洲家庭宽带,延迟约 150~250 毫秒,晚高峰线路质量看运营商 | 国内到港/新/日通常更稳,再到澳洲多一跳;VPS 本身的 IP 也可能被封 |
| 管理通道 | 走隧道内 SSH;隧道挂了就只剩 KVM | VPS 还能当节点的「反向 SSH」备用管理通道,隧道挂了也能进去修 |
| 推荐 | **主** | **备**(或至少只买来当管理备用通道) |

两案在节点程序里是同一个「入口发布器」模块的两种后端,先做 A,B 作为插件位预留。

**2026-10-22 补记(客户答复:不提供也不使用域名;服务器先不急;机器约 11 月 9 日到位)。** 不用域名意味着一切用 IPv4 数字地址:
- 客户端连节点用的地址由鉴权服务器下发(隧道配置单岔路已按此拍板,客户端配置里不出现域名,DNS 仍全走隧道);
- 客户端找鉴权服务器用的地址写在随客户端分发的 `server.json` 里;鉴权服务器首期跟节点同机,所以这个地址就是澳洲家庭宽带的公网 IPv4;
- **因此前提是澳洲宽带有真公网 IPv4 且地址固定或极少变**。澳洲多数 NBN 套餐地址数月不变,部分运营商可加几澳元买固定 IP,但也有运营商默认运营商级共享地址(CGNAT),那种情况下外面根本连不进来。**要客户在机器到位前查两件事:路由器 WAN 口地址是不是 100.64.x.x 段(是 = CGNAT);运营商能不能给固定 IP。** 若是 CGNAT 或地址常变,客户的服务器(固定 IP)就不是「不急」而是必需,鉴权服务器与中继都要搬上去,须在第三周前到位;
- 地址变化的兜底:节点每次检测到公网地址变化就上报鉴权服务器;客户端连不上时按最近一次成功地址重试,并提示「出口地址可能已变,请联系管理员」。没有固定会合点时这是能做到的上限,如实写进交付说明。

## 5. 账户与权限体系:邀请码制 + 薄客户端 + 鉴权服务器(2026-10-22 已拍板 d3)

客户 2026-10-22 说明:要**邀请码制度**,邀请码带期限(一天/一周/一月),过期后软件不能用;分发出去的软件本身**不具备任何功能**,由服务器鉴权并提供服务,防破解;鉴权服务器后面由客户提供,或由我方提供;先做本地端(客户端)。合规责任归属已向负责人说明,负责人知情后决定按此开工;本项目范围内不做支付、商城、多节点、流量计费。

**结构:三个部件,鉴权服务器独立成一个可单独部署的程序。**

```
Windows 薄客户端 ──HTTPS──▶ 鉴权服务器(authserver,FastAPI+SQLite)◀──HTTPS 同步──▶ 澳洲节点(exitnode)
      │                          · 邀请码 / 账号期限 / 设备凭据 / 吊销                        · sing-box 只放行同步来的 UUID
      └──────── 隧道(VLESS+Reality / Hysteria2),凭据来自鉴权服务器,短期有效 ───────────────▶┘
```

- **鉴权服务器**首期部署在澳洲节点上(与节点同机、不同进程),客户之后给了服务器就搬过去,代码不改;对外只开一个 HTTPS 端口。
- **邀请码**:管理员生成,属性 = 期限(天数,1/7/30 或任意)、可用次数(默认 1)、备注;用户在客户端输入邀请码 → 自动建账号 → 账号到期时间 = 兑换时刻 + 期限;到期后登录与续签一律拒绝,客户端明确提示「已到期」。续期 = 再兑一个码(叠加到现有到期时间之后)。
- **薄客户端**:安装包里不含节点地址、不含任何隧道凭据、不含有效配置;每次启动用本地保存的刷新令牌向服务器换**短期会话**(默认 6 小时)并领取当前节点地址 + 本设备 UUID + sing-box 配置;服务器拒绝则客户端什么都连不上。离线破解只能拿到一个空壳。
- **设备凭据**:每个账号可绑设备数上限(默认 2);每台设备一个 UUID;吊销设备或账号到期 → 服务器下一次向节点同步时把 UUID 从 sing-box 配置里去掉并热重载(同步周期默认 60 秒,节点也可被服务器主动推一下)。
- **管理员操作**:首期命令行 + 一页极简网页(生成邀请码、看账号与设备、吊销、延期);只经隧道内地址或白名单访问,**不裸露在公网**。
- **不做**:支付、商城、多节点、流量计费、邀请码分级代理。

数据模型(SQLite 一张库):`invites(code, days, max_uses, used, note, created_by, created_at)`、`accounts(id, invite_code, status, expires_at, device_limit, created_at)`、`devices(id, account_id, uuid, platform, name, refresh_token_hash, last_seen, revoked_at)`、`audit(id, who, what, at)`。令牌只存哈希;所有改动写审计表;节点同步接口用独立的节点密钥认证。

## 6. Windows 一键客户端(首要交付物)

- 技术栈:C# / .NET 9 WPF,发布为**单文件自包含 exe**,内嵌 sing-box.exe 与 wintun.dll(运行时解包到 `%ProgramData%\<产品名>\`)。本机已有 .NET 9 SDK,派单器能用 `dotnet test` 验收。
- 功能:登录 → 一键连接/断开 → 状态(已连接/重连中/需重新登录/需人工处理,与节点状态四档一致)→ 当前出口 IP 显示 → 自动更新(问节点的更新接口,下载校验后替换,失败回退)→ 诊断导出(脱敏)。
- TUN 需要管理员权限:首次运行安装一个 Windows 服务负责起 TUN 与 sing-box,之后界面程序不再弹 UAC;服务和界面分进程,界面崩了隧道不掉。
- **断网保护(kill switch)**:连接期间下发 Windows 防火墙规则,只放行 TUN 网卡出站与节点地址;隧道断开进入「重连中」时规则保留,流量被挡而不是漏;用户主动点断开才撤规则。对应交接文档 A04。
- 兼容:Windows 10 1809+ 与 Windows 11,x64;Win10 需 WebView2?——不用,纯 WPF,避免额外运行时。
- 已知风险:①没有代码签名证书时,首次运行会被 SmartScreen 警告「未知发布者」,要么客户买证书(年费数百到上千元),要么文档教用户点「仍要运行」;②Windows Defender 对内嵌网络内核的程序偶有误报,交付前要在干净 Win10/Win11 虚拟机上实测。

## 7. 节点程序(Linux)

- 系统:Debian 12(Python 3.11,sing-box 官方 deb 源);Ubuntu 24.04 作为兼容目标。
- 命令行 `exitnode`:`init / check / status / diagnose / upgrade / rollback / uninstall`,交接文档建议的七个接口照单。
- 模块(各自独立 systemd 单元,管理面与出口面分进程):
  1. `installer`:幂等安装,所有改动记入清单文件,中断可续跑/可撤回;
  2. `proxy`:生成 sing-box 配置、管理 UUID、热重载;
  3. `publisher`:入口发布器(UPnP + DDNS;VPS 中继预留);
  4. `watchdog`:分层探测(网卡/默认路由 → 上游 → 入口可达 → sing-box 进程 → 真实出口 IP),恢复顺序「重探 → 有限重试 → 重启服务 → 回滚已知可用配置 → 报人工」,退避与频率上限;
  5. `updater`:A/B 版本目录、来源校验、空间与兼容检查、互斥锁、健康检查失败自动回退、断网延后;
  6. `admin-api`:FastAPI + SQLite,账户体系与客户端更新接口;
  7. `nft`:只管 `table inet exitnode` 一张表。
- 配置模型:`/etc/exitnode/config.toml`(不含凭据)+ `/var/lib/exitnode/secrets/`(0600)。设备身份与 IP 无关。
- 日志:journald + 轮转上限可配;诊断包脱敏。

## 10. 风险与待确认

1. **用途与合规**:账户体系意味着多人分发,需客户书面确认;见 §5。
2. **澳洲硬件时间线**:谁在澳洲接线、几号到位,直接决定 A03/A05/A06/A08/A12 能否在工期内验。
3. **IP 被封风险**:家庭宽带 IP 被审查设备封禁的概率低于机房 IP,但不为零;Reality 伪装与备通道是缓解,不是保证。
4. **代码签名**:无证书则 SmartScreen 警告,客户需知情。
5. **节点侧上行带宽**:交接文档记录澳洲套餐上行 50 Mbps、实测约 43 Mbps,多人同时用会分摊,不承诺端到端速度。
