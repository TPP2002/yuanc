# 远程网络出口与自动运维开发交接文档

版本：1.0　整理日期：2026-10-22

开发一套运行于常驻 Linux 节点的远程网络出口与自动运维程序，支持手机和电脑接入、网络迁移、故障恢复、受控更新及可选的独立远程救援。

当前处于需求与方案阶段。已完成现有网络的只读核查和硬件候选评估；尚无已实现的业务程序，尚未购买或接入目标主机，尚未部署隧道、修改现网配置或完成端到端测试。既有设备信息来自 2026-10-18 及之前的记录，实施前应重新核对。

## 开发目标与固定范围

1. 客户端连接后，其互联网流量通过指定常驻节点所在的宽带出口转发；外部服务看到的来源 IP 应与该节点网络的公网出口一致。
2. 支持手机和电脑。首期优先采用成熟协议的现成客户端；具体操作系统和版本待确定。
3. 完成首次安装与账号授权后，日常启动、网络重连、服务恢复及程序更新尽量自动完成。
4. 设备连接到另一台已经正常上网的主路由后，应自动获取网络参数并恢复管理与业务连接，不依赖原有 LAN 地址或网段。
5. 保留现有主路由。新增节点通过有线连接接入，不承担现网主路由替换工作。
6. 不配置 UPS、独立远程电源控制、智能插座或 ATX 电源控制板。IP-KVM 为选配，不能作为核心业务程序运行的前提。
7. 不将路由器刷机、BIOS 自动刷写、无线热点认证自动化、宽带开通或硬件故障修复纳入首期交付。

## 运行环境与硬件约束

| 项目 | 开发基线 |
| --- | --- |
| 主机 | x86-64，N100／N150 级别；8～16GB 内存，256～512GB SSD |
| 网络接口 | 至少一个千兆有线网口；不强制四网口或 2.5GbE |
| 本地接口 | HDMI、USB；主机 BIOS 应支持来电自动开机，并通过实物测试 |
| 操作系统 | 仍处于支持周期内的 Debian 或 Ubuntu Server；先核对网卡与存储驱动 |
| 网络接入 | 现有主路由下接节点，使用 DHCP；不写死部署环境的内网 IP |
| 网络能力 | 公网地址、IPv6、CGNAT、入站可达性及实际中继效果均需现场核查 |
| 性能参考 | 已记录套餐上行 50 Mbps、一次本地实测上行约 42.95 Mbps；不作为端到端速度承诺 |

主机候选为 ASUS NUC 14 Essential N150 与 Beelink EQ14 N150，尚未锁定具体硬件修订或整机配置。开发不应绑定某家商店的预装系统。采购价格和库存不属于本交接基线。

安装前核对 BIOS 版本、来电自启设置、网卡芯片、SSD 与内存配置。既有调查记录提示部分旧版系统与网卡驱动组合存在网络兼容问题；应以选定系统的实际测试结果为准。

## 系统结构与连接方案

建议将接入层、出口转发、管理通道、运维程序和更新程序分开管理。优先复用成熟协议及客户端，不自行设计加密协议。

网络连接关系如下：

- 手机／电脑 → 经认证的加密连接 → Linux 出口节点 → 现有主路由 → 互联网。
- 维护端 → 经认证的管理连接 → Linux 节点的受限管理入口。
- 维护端 → 可选 IP-KVM 自身的管理连接 → HDMI 画面与 USB 输入控制 → Linux 节点。

WireGuard 与 Tailscale 出口节点均为候选。先验证目标网络上的可达性、直接连接与中继表现、身份授权方式和依赖服务，再确定首期实现。不得把原生 WireGuard 默认视为可穿透所有 NAT，也不得把第三方组网默认视为在任何网络都可用。

出口服务异常时，尽量保留独立的管理服务。管理服务与出口服务使用分开的进程或服务单元；仍共用同一操作系统，不能宣称能覆盖整机失效。选配 IP-KVM 时，其网络与电源不得由待修复节点提供。

## 核心开发需求

### 安装与初始化

提供单一安装入口，完成环境检查、依赖安装、配置生成、服务注册、权限配置和结果输出。首次系统安装、设备接线及账号登录授权仍需明确的初始化步骤，不承诺全新硬件直接零操作上线。

安装流程必须幂等：重复运行不重复创建规则或服务，不重置已授权设备身份，不覆盖用户已确认的有效配置。安装中断后可续跑或撤回本次改动。输出成功项、失败项与下一步操作，不能仅凭安装进程退出就报告连接成功。

建议提供 init、check、status、diagnose、upgrade、rollback、uninstall 等管理操作；这些是待实现的接口建议，当前没有可执行命令。

### 出口转发与客户端

提供经指定节点访问互联网的连接配置，首期以全流量出口为基线。分流规则作为后续扩展，不得无提示改变已选择的出口策略。

同时处理 IPv4、IPv6 和 DNS。IPv6 应经指定出口转发；暂不支持时，应在客户端连接模式中阻止 IPv6 绕过隧道。DNS 必须遵循已配置的出口策略，不得静默改用客户端原网络解析。使用加密 DNS 时，按实际网络路径验证，不以解析器所属地区单独判定是否泄漏。

客户端在启用指定出口模式时，隧道失败不得静默切回原网络继续承载受控流量。具体阻断方式应按选定客户端平台验证；不支持的平台必须明确标为不满足该项验收。用户主动断开连接时，应按明确规则恢复原有网络配置。

支持设备授权、撤销和凭据更新。身份失效时输出可操作的状态，不使用无限重试代替重新授权。

### 网络迁移与自动重连

节点启动时使用 DHCP 获取地址、网关和 DNS。设备身份与密钥独立于当前 IP 保存，不能把原局域网地址作为永久身份。

上游重启、地址变化、链路恢复或更换网段后，重新检测网络并恢复经认证的管理与出口连接。优先采用不依赖手工端口转发的接入方式；直接连接与中继的选择应可观察。

网络迁移的前提是新上游已经能正常访问互联网。需要拨号凭据、门户认证或重新开通服务的网络，不属于自动接入能力。

### 运行状态与自动恢复

分别检查网卡／默认路由、上游连通性、管理连接、出口进程和实际流量路径。单个外部探测地址失败不能直接触发整机重启；区分上游中断、进程故障、授权失效与配置错误。

恢复顺序采用：重新探测 → 有限重试 → 重启受影响服务 → 恢复已知可用配置 → 报告人工处理状态。重试使用退避与频率上限，防止重连、重启和日志写入风暴。

默认不以整机反复重启作为自救手段。若增加主机重启或硬件看门狗，需单独验证触发条件、次数上限及管理通道恢复能力。

状态至少区分：正常、重连中、需重新授权、需人工处理。提供简明状态及机器可读诊断输出，记录当前版本、网络状态、直接／中继连接方式、最后成功时间和故障原因。

### 程序更新与回退

自动更新范围首先限于本项目程序和配置。操作系统大版本升级、内核更换和 BIOS／固件刷写不混入常规自动更新。

更新流程包括：可信发布来源校验 → 下载到临时位置 → 检查磁盘空间与配置兼容 → 保留已知可用版本和配置 → 切换版本 → 检查服务及管理连接 → 失败自动回退。更新验证应覆盖管理连接和实际出口，不以进程存活作为唯一成功条件。

处理下载中断、错误配置、不完整安装、更新进程被终止和更新后无法连通等情况。并发更新须互斥，版本与配置应配套回退；不能恢复不兼容的半套文件。不可逆的配置迁移不得进入无人值守更新流程。

网络整体中断时，应延后依赖外网的更新，不反复切换版本。恢复后重新验证。更新程序本身出错不能阻止已有稳定服务启动。

## 管理与信息保护要求

- 管理入口须经认证访问，不将 SSH、管理面板或 KVM 管理端口直接作为无保护公网服务。
- 使用每设备独立身份，支持最小权限授权与撤销。密钥、令牌和密码不得写入代码仓库、安装示例或普通日志。
- 只管理本项目创建的服务、路由和防火墙规则。禁止清空现有规则或通过关闭防火墙解决连接问题。
- 远程修改配置前保留可恢复副本，并提供连通性检查与失败回退，避免修改后锁死管理入口。
- 日志轮转、容量限制和诊断导出应可配置；诊断包默认隐藏凭据及不必要的设备标识。
- 卸载时清理本项目资源并恢复受影响配置，不删除无关服务、用户数据或网络规则。

## 可选独立救援与恢复边界

IP-KVM 候选为 GL.iNet Comet GL-RM1，最终版本和附件待核实。需要有线联网、独立供电、HDMI 画面采集、USB 输入控制，以及 BIOS 阶段访问和虚拟介质能力。供电方式、适配器和线材按具体版本确认。

KVM 应单独接到上游网络，不依赖 Linux 节点的网络转发、USB 供电或正在修复的服务。其远程连接应在客户端实际网络验证；可用性不能由产品说明代替。

验收仅覆盖主机仍通电且能输出画面、响应输入时的启动排障与系统修复。完全卡死、硬件损坏、无法唤醒的关机、主路由失效或上游断网，仍可能需要现场处理。

不提供停电期间续航或远程硬断电能力。恢复供电后，依靠已配置且经过实测的 BIOS 来电自启、系统服务自启动和网络重连恢复运行。

## 验收清单

所有验收保留软件版本、系统／内核版本、硬件型号、网络条件、步骤、原始结果与失败记录。厂商功能声明、安装成功和局域网测试均不能替代端到端验收。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 重复安装与中断续跑 | 不重复规则、不丢失身份；失败后能恢复有效配置 |
| A02 | 手机与电脑接入 | 分别完成认证、连接、断开与重连，记录客户端系统和版本 |
| A03 | 指定网络出口 | 从独立外网验证 IPv4 出口一致；IPv6 经指定出口或被阻断，不能绕行；DNS 路径符合策略 |
| A04 | 隧道中断 | 启用出口模式时受控流量不静默改走客户端原网络；状态正确提示 |
| A05 | 地址及上游变化 | 主路由重启、地址变化后自动恢复；分别记录直接连接与中继结果 |
| A06 | 更换路由器和网段 | 接到另一台已联网主路由后自动获取地址并恢复，无需现场修改内网地址或端口转发 |
| A07 | 服务故障 | 仅停止或终止出口进程后按策略恢复；管理连接保持可达，无重启风暴 |
| A08 | 断电恢复 | 实物验证来电自启、服务启动和重新联网；记录恢复耗时，不要求停电期间在线 |
| A09 | 更新失败 | 覆盖下载中断、配置错误和新版本健康检查失败，能够恢复已知可用版本与配置 |
| A10 | 授权撤销与失效 | 已撤销设备不能继续获得访问；过期凭据正确提示，不无限尝试 |
| A11 | 可选 KVM | 出口服务停止或系统启动异常时，KVM 仍可连接；验证 BIOS 操作及虚拟介质；未采购时记不适用 |
| A12 | 性能与连续运行 | 在客户端实际网络记录吞吐、时延、丢包、重连和温度／错误日志，区分直接与中继路径 |

吞吐下限、恢复时间上限、日志保留期和连续运行时长尚未约定。先完成可重复的基线测试，再把验收数值写入发布标准；不得将尚未测得的性能写成已保证指标。

## 交付物与接手顺序

交付物包括：源代码与依赖清单、配置模板、幂等安装／卸载入口、服务单元、状态与诊断工具、版本发布及回退机制、手机和电脑接入说明、网络迁移接线说明、故障处置说明，以及验收记录。示例配置不包含真实凭据。

建议按以下顺序推进：

1. 确认最终主机、客户端操作系统、可维护的 Linux 版本和网络接入条件；验证来电自启及网卡驱动。
2. 用成熟协议完成最小出口原型，先验收外部可见 IPv4／IPv6 与 DNS 路径。
3. 建立经认证的管理通道，再实现安装、状态检查、自动重连及服务恢复。
4. 实现配置备份、版本更新与回退，执行故障注入及网络迁移测试。
5. 按是否采购 KVM 完成独立救援验证，最后执行实际网络性能和连续运行测试。
6. 交付可复现的安装和验收记录，将已实现、已部署、已实测及未通过项分别列出。

当前待确定项：最终硬件与是否选配 KVM；手机和电脑的系统版本；首期连接方案及账号管理方式；目标网络中的可达性与中继效果；量化性能和恢复指标。设备到位前可完成程序接口、配置模型、安装与回退设计，但实机相关验收不得提前标为通过。
