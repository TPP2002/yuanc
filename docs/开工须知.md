## 1. 这个项目是什么(一段话)

负责人接的外包活。客户在中国大陆,自购一台 x86 小主机(N100/N150 级,客户称「软路由」)放在**澳大利亚**家庭宽带下当出口节点;客户的 Windows 电脑(Win10/Win11)和手机(安卓 11+,手机端可延期)连上节点后,全部上网流量从澳洲出口,外部看到的来源 IP 是澳洲家庭宽带 IP。交付物三块:①节点程序(Linux,安装/自愈/自更新/账户与设备授权);②**Windows 一键客户端 .exe**(首要交付);③账户与权限体系(客户似乎要分发给多人,用途待客户书面确认)。客户给的交接文档是 `docs/交接/远程网络出口与自动运维开发交接文档.md`,我方方案是 `docs/design/方案v2-中国客户端-澳洲出口.md`。工期四周(2026-10-23 至 2026-11-19)。

## 3. 开工三查(缺一不许动代码)

1. 新鲜度:`git fetch origin`,核对工位不落后 `origin/main`;多工位一律完整绝对路径。
2. 看板:项目 id `yuanc`,`node ~/.claude/dashboard-release/cli/index.cjs brief <卡> --project yuanc`。板文件 `.dashboard/` 不入库(写在 `.git/info/exclude`),远程会话看不到看板,以文档 + git 为准,回本机补登。
3. 正本:读任务卡指向的设计正本 + `docs/口径速查表.md`;协议、端口、账户模型类设计动手前先查速查表。

## 4. 红线(任何任务都生效)

1. **只管本项目创建的服务、路由、防火墙规则**;禁止清空现有规则、禁止关防火墙解决连通问题;nftables 只动自己的表。
2. **凭据不落代码库、不落示例、不落普通日志**;诊断包默认脱敏。示例配置里的密钥一律占位符。
3. **隧道断了不许静默回落到客户端原网络**;做不到的平台必须明说「不满足」,不许假装满足。
4. **安装、更新一律幂等、可回退**;不以进程存活当成功,要验到管理通道和真实出口。
5. **反阉割**:交接文档里的需求做不到就如实列冲突给选项,不许悄悄降级;真机未测的项不许标通过。
6. **后台静默**:Windows 客户端拉起的任何子进程(sing-box、netsh、计划任务)一律隐藏窗口。
7. 账户体系只做「管理员建用户、用户登录领设备凭据、到期/禁用/设备数上限」;**不做支付、不做多节点、不做商城**。

## 5.1 PR 的 CI 覆盖哪几项(skill §8.D;2026-10-22 起 CI 已落地,下列项本机不再重跑)

- 覆盖(`.github/workflows/ci.yml`,PR 每次 push 触发):`python -m ruff check node authserver`、`python -m pytest -q`(node/tests + authserver/tests)、`dotnet test winclient`(仓里有 .sln 才跑)。
- 出包检查(`.github/workflows/winclient-package.yml`,流程名「客户端出包检查」,2026-11-28 起):在检查机上跑一遍 `scripts/release/build-winclient.ps1`,打正式包并过脚本自带的三项检查(发布目录只有 exe 和 pdb、有主程序、不超过 1 GiB),不到一分钟;PR 每次 push 与主干推送都跑,只改 `docs/**`、`node/**`、`authserver/**`、`**.md` 时不跑。一个提交可能有两个流程的结果,读结论时按提交号把两个都核到。
- 跑在哪:**负责人本机的自托管 runner**(服务 `actions.runner.TPP2002-yuanc.yuanc-local-win`,目录 `C:\actions-runner-yuanc`,标签 `yuanc-local`,NETWORK SERVICE 延迟自启)。私有仓用 GitHub 托管机走计费,2026-10-22 实测账户计费失败导致作业「三秒红」(annotation 写 payments have failed / spending limit),故改自托管。仓库变量 `CI_RUNS_ON=yuanc-local` + `CI_PYTHON_MATRIX=["system"]` 成对生效;两个一起删 = 切回 GitHub 托管(ubuntu/windows-latest + Python 3.11/3.12 矩阵),workflow 不用改。
- 自托管口径的两条已知差异:①Python 用本机 3.14,3.11 兼容性靠 ruff `target-version = py311` 与真机(Debian 12)验证兜底;②跑在 Windows 上,与 Linux 路径/权限相关的行为以真机验证为准。台账写「CI 绿」时注明是自托管。
- CI 转圈不动先查 runner 在不在线:`MSYS_NO_PATHCONV=1 gh api repos/TPP2002/yuanc/actions/runners --jq '.runners[] | "\(.name) \(.status)"'`;离线就 `Start-Service actions.runner.TPP2002-yuanc.yuanc-local-win`。
- 不覆盖(本机照跑,先挂号):证红、VM 真机验证、Windows 真机验证(TUN、防火墙、UAC)、要提交进库的生成物。
- CI 对草稿 PR 免不免跑:否(本仓 `on: pull_request` 不分草稿)。
- 读 CI 结论必须核 commit SHA 与头提交一致,别拿旧 run 的绿合新头。

## 5.2 施工方(skill §17.0;默认派单器,所有项目生效)

- 写代码的活一律派派单器(工单不写 engine,施工方顺序照全局约定 `~/.claude/CLAUDE.md`),Claude 只定契约、派单、自审 diff、收官。跨仓派法:`cd F:/stock-rogue && npx tsx scripts/codex/codex-dispatch.ts dispatch --task .codex/jobs/<slug>.json --repo E:/yuanc`,工单里 `"repoRoot": "E:/yuanc"`。
- 本仓跑法:没有 package.json,派单器按 Python 仓探测(根目录 `pyproject.toml` 带 `[tool.pytest.ini_options]`);定向测试写 `test:targeted` 指到单个 `test_*.py`;ruff、dotnet 等写成 `command` 验收项(argv 数组)交派单器经调度台跑。
- 本仓特有的红线与坑一律写进工单 `background`:上面第 4 节七条;工人工位里不许装依赖(缺依赖停下交 blocked);Windows 子进程 `CreateNoWindow`/`windowsHide`;不许读写 `secrets/`。
- 自干只限 skill §17.0 例外表四种,开工第一句回复写「施工方=Codex/Claude(工单 slug)/自干(例外编号)」。
