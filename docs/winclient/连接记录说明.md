# Windows 客户端连接记录说明

这份说明写清连接记录写在哪、每种行的原文与什么时候写、哪些内容不会写进去,以及怎么把它拿出来。记录由后台服务的 `ClientController` 通过记录口逐行写出,一次调用写一行,文字按本文原文。

## 文件位置与轮转

- 位置:后台服务数据目录下的 `run/connect.log`(例如 `%ProgramData%\YuanC\run\connect.log`);日志对象外层还套一层脱敏,带 `token=`、`password=` 这类标签的值与已登记的凭据值会先替换成「[已隐藏]」。
- 每行开头是协调世界时(UTC)的 ISO 时间戳,空格之后是记录文字。
- 轮转规则照 `RollingFileLog` 的实际实现:单个文件上限 1 MiB,保留 3 份历史文件。写入前先算这一行加上去的字节数,超过上限就整体后移:当前的 `connect.log` 改名 `connect.log.1`,原来的 `.1` 改成 `.2`,`.2` 改成 `.3`(覆盖旧的 `.3`);也就是最多 4 个文件(当前 1 份 + 历史 3 份)。
- 单行超过 16 KiB 字符部分(且不超过文件上限八分之一)会截断并在末尾加「[已截断]」;本单写出的行远小于这个上限。
- 记录口写失败(磁盘满、权限不足等)只会丢掉那一行,不影响连接与断网保护流程。

## 连接请求与早退检查(ConnectAsync)

拿到串行锁后第一件事就写一行:

```
连接请求：来源=<用户|自动>，状态=<状态名>，保护=<有|无>，恢复记录=<有|无|读不到>
```

- 来源:用户点「连接」写「用户」,后台自启的自动连接写「自动」。
- 「状态名」见下文状态表;「保护」看本进程当前是否套着断网保护;「恢复记录」读断网保护的恢复记录状态,读取时抛任何异常写「读不到」。

任何一项检查没过、连接没有真正开始时,各写一行:

```
连接未开始：未配置服务器
连接未开始：已在连接或已连接
连接未开始：指定程序名单为空
连接未开始：恢复记录与代理范围不一致
连接未开始：读不到网卡地址
连接未开始：网卡上有公网 IPv4
连接未开始：浏览器正在运行，等用户再点一次
```

通过全部检查、算出这次是不是首次尝试之后,写:

```
开始连接：模式=<自用模式|邀请码模式>，代理范围=<全部流量|仅指定程序 N 个>，首次尝试=<是|否>
```

N 是名单里的程序个数。首次尝试指进入时既没有保护、也没有恢复记录的那次连接。

`finally` 里、发出快照之前,再写一行(提前返回的也写):

```
连接请求结束：状态=<状态名>，保护=<有|无>
```

## 取会话与续期

```
取会话：<AuthResult 枚举名>
```

拿到会话应答后写,例如「取会话：Ok」「取会话：Network」。应答是 Ok 但会话或账号已到期时,再写一行「取会话：会话或账号已到期」,然后按原有规则进「需重新登录」。

```
续期：<AuthResult 枚举名>
```

邀请码模式在会话有效期八成处续期,拿到应答后写这一行。

## 状态迁移

```
状态：<旧状态名>→<新状态名>
```

控制器记住上一次写进记录的状态,控制器处理每一步效果之前与每次状态迁移收尾时各核对一次,只有真的变了才写。六个状态名固定:

| 状态 | 记录里的名字 |
|---|---|
| Disconnected | 未连接 |
| Connecting | 连接中 |
| Connected | 已连接 |
| Reconnecting | 重连中 |
| NeedsLogin | 需重新登录 |
| NeedsManual | 需人工处理 |

## 动作起止与用时

除「显示提示」以外,每个动作开始前写「动作开始：<动作名>」,做完写:

```
动作结束：<动作名>，用时 <毫秒> 毫秒
```

动作抛出异常时写:

```
动作出错：<动作名>，用时 <毫秒> 毫秒，<异常链>
```

然后原样把异常再抛出去。用时取整毫秒,计时用 `System.Diagnostics.Stopwatch`。动作名固定:

| 动作 | 记录里的名字 |
|---|---|
| ApplyKillSwitch | 套用断网保护 |
| UpdateKillSwitchNode | 更新节点规则 |
| RemoveKillSwitch | 撤销断网保护 |
| StopTunnel | 停止隧道 |
| StartTunnel | 启动隧道 |
| ShowMessage | 显示提示(不写起止) |
| ScheduleBackoff | 安排退避 <秒> 秒 |

异常链由 `ConnectJournal.Describe` 加工:最多四层「类型短名：消息」,换行换成「 | 」,IPv4 换成「[地址]」,`C:\Users\<用户名>` 换成 `C:\Users\[用户]`,单条消息超过 300 字截断并加「…」。

### 启动隧道与套用断网保护的特殊分支

- 启动隧道碰到的三种异常,在原有处理之前各写一行「启动隧道没成功：<异常链>」(找不到内核、配置数据无效、输入输出异常或超时)。
- 已经持有保护时重新套用断网保护失败,在原有处理之前写「套用断网保护没成功，隧道保持：<异常链>」,隧道保持,提示按原有规则给。
- 隧道掉线事件排进串行锁的回调里,处理掉线之前写「隧道掉线」(不写在事件线程上)。

## 出口核验(CheckExitAsync)

- 拿到出口地址:与下发节点地址一致写「出口核验：已核验」,不一致写「出口核验：不一致」。
- 这一次没有结果、还要再试:写「出口核验：第 <attempt> 次没有回应」。
- 一轮以「无法核验」收场,在测试包自动断开那一段之前写「出口核验：无法核验，已连续 <轮数> 轮」。
- 这些行一概不写地址本身。

## 断开(DisconnectAsync)

- 被浏览器正在运行的提醒拦下:「断开未开始：浏览器正在运行，等用户再点一次」。
- 拿到串行锁后:「断开请求：状态=<状态名>，保护=<有|无>」。
- 正常走完(没有进异常处理):「断开完成：环境恢复=<成功|失败>」。

## 启动恢复(InitializeAsync)

拿到串行锁后写:

```
启动：保持保护=<是|否>，自动连接=<是|否>，恢复记录=<有|无|读不到>，模式=<自用模式|邀请码模式|未配置>
```

走接回断网保护的分支,写「启动：接回断网保护，随后自动连接」。走启动恢复的分支,在断网保护恢复与环境恢复都做完之后写:

```
启动：已做启动恢复，提醒=<有|无>
```

## 巡检(PatrolAsync)

每一轮巡检在网卡巡检之后核对巡检文字:

- 本轮巡检文字既不是「正常」、也不以「已为新出现的」开头,并且与上次写进记录的不同,写「巡检：<加工后的巡检文字>」并记住。
- 本轮是「正常」而上次记的是异常,写「巡检：恢复正常」并清空记忆。
- 同一种异常状态连续多轮只写一次。

## 失败处理与放弃并恢复

以下两种行沿用上一张单,原文不变:

```
连接失败：<异常链>
放弃并恢复：<短语>，撤销=<成功|失败|不需要>
```

首次尝试期间任何异常都会自动恢复原来的网络;恢复时各步出错补写这些行(异常链同样由 `ConnectJournal.Describe` 加工):

```
停止隧道没成功：<异常链>
撤销断网保护没成功：<异常链>
恢复网卡没成功：<异常链>
恢复环境没成功：<异常链>
```

## 记录里不会出现的内容

- 节点地址、出口地址、端口之外的连接参数都不写;出口核验只写结果,不写地址。
- 令牌、配对内容、邀请码不写。
- 程序名单里的路径不写,只写名单个数。
- 会话来源的模式只有「自用模式」「邀请码模式」两种,可以写。
- 记录读取失败只写「读不到」,错误详情也不带地址。

## 怎么拿到

界面「更新与诊断」页的「导出诊断」会把诊断报告写到本地文件,交管理员排查;连接记录 `run/connect.log` 就在后台服务数据目录的 `run` 子目录里,可直接取用。记录口由后台服务接在 `run/connect.log`(脱敏后写 `RollingFileLog`)。

## 真机待验证（本单未执行）

- 真机第一次点连接失败时,记录里能按顺序看到「连接请求：…」「开始连接：…」「动作开始/结束/出错…」与「连接失败：…」「放弃并恢复：…」,并且电脑网络自动恢复。
- 真机上隧道掉线一次,记录里能看到「隧道掉线」与随后的「状态：已连接→重连中」。
- 真机连上后拔网线,出口核验按 5 次没有回应收场,记录里出现「出口核验：第 1 次没有回应」到「第 5 次没有回应」与「无法核验」那一行。
- 真机把系统防火墙配置档关掉后巡检,记录里只写一次「巡检：…」,恢复后再写一次「巡检：恢复正常」。
- `run/connect.log` 超过 1 MiB 时的轮转(`connect.log.1` 到 `.3`)在真机上确实发生。
