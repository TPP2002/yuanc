# Windows 客户端界面说明

## 布局与五页

主窗口默认 880×600，最小 760×540，居中启动。左侧为 200 宽的侧栏，右侧为当前页面；侧栏底部显示后台服务状态和版本。键盘焦点按侧栏、页内自上而下移动，可交互控件有统一焦点描边。

| 页面 | 内容与操作 |
| --- | --- |
| 连接 | 模式徽章、连接状态英雄卡、固定宽度主按钮、常驻消息槽，以及出口 IP、断网保护、环境自检、环境一致性四行状态；需要重新登录时提供“去兑换邀请码”；浏览器正在运行时先提醒,「仍然继续」按钮两分钟内直接执行。 |
| 代理范围 | 全部流量与仅指定程序两张选择卡；添加、移除程序，长路径截断显示。连接中禁止修改并显示原因。 |
| 环境一致 | 环境开关、当前自检状态和自检明细；后台服务未就绪时解释禁用原因，没有明细时显示空态。「强制恢复默认环境」按钮:仅在后台就绪、已断开且无断网保护时可用,按记录恢复或执行不改系统时区的无记录兜底。澳洲专用浏览器卡片(创建快捷方式按钮与结果提示,不依赖后台服务)。「在浏览器里复核」按钮:生成本地页面并用默认浏览器打开,不依赖后台服务。 |
| 账号与配对 | 导入配对文件、输入并兑换邀请码、清除本机配对文件；保留原有命令限制。 |
| 更新与诊断 | 后台服务与界面版本、上次检查时间、更新消息、检查更新，以及导出诊断。导出结果显示在本页导出按钮下方；任何情况下都会写出文件，内容已脱敏，不含出口 IP。 |

关闭窗口仍然只是隐藏到托盘；隧道与断网保护由后台服务管理。托盘菜单仍为打开窗口、连接、断开、退出界面（隧道不受影响）。配对文件和程序选择对话框的行为保持原有语义。

## 状态瓦片与状态表

状态瓦片沿用看板的语法：颜色表达语义，记号表达状态类别，边框灯条表达正在进行的工作，实心表示已完成，半透明表示未启用。记号均为 Geometry，不以文字符号充当图标。

| 属性 | 取值与含义 |
| --- | --- |
| Tone | N 中性、Info 进行中、Warn 需注意、Ok 正常、Bad 故障。 |
| Glyph | Ring、Dots、Bars、Check、Spin、Ask、Bang、X、Plug，路径来自设计样张。 |
| Flow | None 静止、Forward 正向、Reverse 反向、Fast 快速；动画关闭时用对应语义实色边框。 |
| Filled / Dim | Filled 使用语义色填充、反色记号；Dim 整体不透明度为 0.5。 |
| TileSize | 英雄卡为 56，状态行为 20；边框、圆角与记号描边按设计分别设置。 |

状态表以 [DESIGN.md 第 4 节](../design/2026-10-22-客户端界面/DESIGN.md) 为正本。纯函数映射位于 `winclient/WinClient.App/Presentation/StatusPresentation.cs`：`Build` 生成英雄卡、主按钮与托盘展示，`Exit`、`Guard`、`SelfCheck`、`Environment` 生成四行状态。它不执行命令、不依赖 WPF。连接成功但断网保护异常时，连接瓦片仍表示隧道已连接，副标题显示原始告警并使用警示色，托盘切为警告态；错误消息不会因界面改版被隐藏。

## 等宽片段与延时提示

`MonoText` 附加属性把 IP、点分版本号、IPv6 切成引用 `Yc.Font.Mono` 动态资源的等宽片段，用在连接页英雄卡副标题、四行状态正文及更新页进行中一行；其余文字继承原字体和前景色，状态映射字串不变。**真机未测**：需在真机查看 IP 变化时宽度不跳，并确认深浅主题下等宽字体跟随资源。

更新页「更新进行中」一行要持续超过 1 秒才出现（`UpdateIndicatorDelay`，到达 1 秒阈值时显示），结束立即隐藏，再次开始重新计时。**真机未测**：需在真机确认快速检查更新不闪。

## 系统主题与标题栏

`ThemeManager` 只读当前用户注册表 `Software/Microsoft/Windows/CurrentVersion/Themes/Personalize` 中的 `AppsUseLightTheme`：DWORD 为 0 时使用深色，其余情况或读取失败使用浅色。启动时应用，订阅 `UserPreferenceChanged` 后在界面线程重新检测并替换颜色字典，退出时退订。

窗口初始化和主题变化时调用 `DwmSetWindowAttribute`，先尝试属性 20，失败再尝试 19，深色传 1、浅色传 0。Windows 10 1903 以下若无效即忽略，不阻止窗口使用。

## 动效清单与系统开关

`MotionSettings.Enabled = Override ?? SystemParameters.ClientAreaAnimation`。`Override` 供测试使用，产品跟随系统；`UserPreferenceChanged` 时刷新。系统关闭“动画效果”后全部动效停止，新动效不启动，直接显示最终状态。`StatusTile.IsFlowing` 同时检查 Flow 和动画开关。

| 动效 | 行为 |
| --- | --- |
| 按钮反馈 | 按下缩放与颜色反馈 120 毫秒；禁用不透明度 55%，忙碌时显示对应处理中标签。 |
| 环境开关 | 40×22 轨道，滑块 180 毫秒移动；每个开关实例使用独立的 TranslateTransform。 |
| 页面切换 | 淡入并从下方 6 像素归位，180 毫秒。 |
| 四行状态首次显示 | 依次延迟 0/30/60/90 毫秒，淡入 140 毫秒，只播一次。 |
| 出口 IP 文字变化 | 淡入并从下方 4 像素归位，300 毫秒。 |
| 灯条 | Forward/Reverse 为 3.4 秒线性循环，分别从 0 移至 1/-1；Fast 为 2.4 秒。 |
| Bars | 三根柱子从底部缩放，0.25 至 1 再回到 0.25，各错开 0.25 秒，周期 2.4 秒。 |
| Spin | 回旋箭头旋转至 -360 度，周期 3.2 秒。 |
| Ask | 不透明度 1 至 0.45、缩放 1 至 0.9，周期 2.4 秒。 |
| Dots | 三点错开上下移动与透明度变化，周期 1.6 秒。 |
| Check | Filled 变为 true 时用描边偏移画出勾形，600 毫秒，只播一次。 |
| Tone 变化 | 内层底色过渡 180 毫秒。 |

Bars、Spin、Ask、Dots 只有在 Flow 非 None 且动画开启时才运行。悬停样式仅由鼠标状态触发，键盘焦点使用独立的 2 像素描边。

## 托盘五态

程序图标使用 `Assets/app.ico`。托盘图标按状态使用 `tray-n/info/ok/warn/bad.ico`，启动时一次性加载，退出时全部释放。

| 托盘态 | 典型情形 |
| --- | --- |
| N | 未连接、需要安装后台服务。 |
| Info | 正在连接、正在重连。 |
| Ok | 已连接且断网保护正常。 |
| Warn | 后台服务需要修复、需要重新登录、已连接但断网保护告警。 |
| Bad | 后台服务不可用、需要手动处理。 |

托盘提示为“澳洲出口客户端 · ”加状态标题，最长 63 字符。图标随 Hero 更新，不增加气泡通知。

## 界面测试与截图

`winclient/WinClient.UiTests` 使用 `net9.0-windows`，只引用既有测试工程所用的三个测试包及相同版本。状态映射测试覆盖英雄卡和四行状态的分支；主题测试核对键集合、字典替换和动画开关；渲染测试核对画面非纯色、主按钮位置尺寸固定，以及按钮文字存在、前景色不同于背景色、文字宽度有效。

构建与测试命令由统一调度台或派单器验收通道执行；施工工位不直接启动测试进程：

```text
dotnet build winclient/WinClient.sln -c Release --nologo
dotnet test winclient/WinClient.sln -c Release --no-build --nologo
```

全部渲染和主题测试共享同一个 STA 线程夹具。测试宿主的入口程序集不是 WinClient.App，所以资源字典一律按程序集名定位，夹具里对 ResourceAssembly 的赋值只在允许时进行。赋值失败只捕获测试宿主锁定入口程序集所产生的 InvalidOperationException，其他异常正常报错。

渲染通过 `ApplyPreview` 喂入快照，第三个参数声明「连接可用」，Ready 状态默认按启用态渲染；不传第三个参数时仍保持无后台连接的禁用行为。以 880×600、96 DPI 离屏绘制 MainShell；不建立后台服务连接，不弹出窗口，不安装服务，不写注册表。环境页预览使用一份固定的八项自检明细样本,不随产品自检项数变化，演示版本、出口地址和程序路径只在测试数据中出现。

截图写入仓库根目录 `build/ui-shots/`：

- 连接页：`connect-need-install.png`、`connect-need-repair.png`、`connect-unavailable.png`、`connect-disconnected.png`、`connect-connecting.png`、`connect-connected.png`、`connect-connected-warning.png`、`connect-reconnecting.png`、`connect-needs-login.png`、`connect-needs-manual.png`。
- 代理范围页：启用态 `page-routing.png` / 禁用态 `page-routing-unavailable.png`。
- 环境一致页：启用态 `page-environment.png` / 禁用态 `page-environment-unavailable.png`。
- 账号与配对页：启用态 `page-account.png` / 禁用态 `page-account-unavailable.png`。
- 更新与诊断页：启用态 `page-update.png` / 禁用态 `page-update-unavailable.png`。
- 连接页十张，其他四页各两张；深色对应文件在扩展名前加 `-dark`，浅深合计 36 张。

截图前检查自身及所有祖先 Visibility 均为 Visible 的文字：启用态不应出现「未就绪」，且连接可用；其他四页的禁用态使用 Unavailable 状态，必须出现「未就绪」，且连接不可用。连接页需要安装、需要修复、不可用三种状态不做这条提示断言。

测试从运行目录向上寻找含 `winclient/WinClient.sln` 的仓库根目录，截图和位置记录仅写入 `build/`。渲染测试不依赖交互式会话，在自托管检查机（服务账户、非交互）上同样实际绘制并断言，2026-10-24 实测。

### 基准图比对

基准图在 `winclient/WinClient.UiTests/Baselines/`，每张截图与同名基准逐像素比对：任一颜色通道差超过 16 才算不同像素（差 ≤16 视为相同），不同像素超过 0.1% 判失败。全部 36 张比对后统一报告失败，差异图写入 `build/ui-shots/diff/`，不同处标红，相同处显示亮度减半的灰色。

界面有意改动时，本机设 `YC_UPDATE_UI_BASELINE=1` 跑一次 UiTests 更新基准，连同界面改动一起提交，并在 PR 里说明哪些图变了；检查机上设了该变量会直接失败。CI 把 `build/ui-shots` 上传为构件 `ui-shots-<运行号>`，保留 7 天；账户存储不可用时上传失败不影响检查结论。

基准图只代表本机（自托管检查机）的渲染结果。当前基准由交互会话生成，检查机以服务账户在非交互会话渲染，字体平滑可能有细差，这正是设置单通道容差 16 与不同像素占比 0.1% 的原因；超标仍失败，不自动放宽或跳过。换机器后字体或缩放不同可能导致画面整体不同，届时须在新机器上重建基准。

## 真机待验证

以下项目尚未做真机验证，不能用构建或离屏截图代替：

- 150% 缩放下的文字、长路径、焦点框和最小窗口布局。
- 系统切换浅深主题时，深色标题栏是否正确更新。
- 系统关闭“动画效果”后，瓦片、开关、按钮、切页和文字更新是否全部静止。
- 浅色与深色任务栏上的五态托盘图标是否清晰可辨。
- 连接、断开、重连过程中主按钮是否始终保持位置与尺寸，忙碌文字是否完整可读。
