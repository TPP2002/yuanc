# Windows 客户端服务化与自启

## 角色、权限与安装位置

同一个单文件程序由自定义 `[STAThread] Main` 按第一个参数选择角色，界面清单为 `asInvoker`：

| 参数 | 行为 |
|---|---|
| 无参数 | 普通用户界面，立即显示窗口 |
| `--tray` | 普通用户界面，只显示托盘 |
| `--service` | 后台服务宿主，不创建 WPF Application |
| `--install` | 管理员安装动作，失败返回 1 |
| `--repair` | 管理员动作，核验并修正数据目录权限，启动未运行的后台服务 |
| `--uninstall` | 管理员卸载动作 |
| `--uninstall-prompt` | 系统「应用和功能」里点卸载时运行：先弹确认框，再做卸载动作，最后弹结果 |
| `--apply-update` | 旧后台启动的更新助手，不创建界面 |
| 未知参数 | 向标准错误输出中文说明并返回 2 |

后台服务名 `YuanCService`，显示名「YuanC 澳洲出口连接服务」，以 LocalSystem 运行，依赖 BFE，开机自动启动。服务失败后由系统依次间隔 5、10、30 秒重启，失败计数重置周期为 86400 秒，并启用非崩溃失败动作。无需额外看门狗。

安装程序只复制当前单文件 exe 到 `%ProgramFiles%\YuanC\app\<Version>\YuanC-Client.exe`。Version 取程序集 InformationalVersion 去掉 `+` 后缀，默认与 Directory.Build.props 一致。相同 SHA256 跳过复制；服务配置及注册表同值重复安装不改变最终状态。任一步失败返回 1 并输出中文原因，不回滚已成功步骤，可以重新运行。此目录布局也用于自用模式自动更新：后台验签和暂存，旧版启动 `--apply-update` 助手完成服务切换、健康检查与回退，见 [自动更新说明](自动更新说明.md)。

登录自启写入 `HKLM\Software\Microsoft\Windows\CurrentVersion\Run` 的 `YuanC` 值，内容是带引号的目标 exe 绝对路径及 `--tray`。服务自启不依赖用户登录；用户登录后才启动托盘界面。

### 开始菜单图标、桌面图标与卸载入口

安装的最后一步（后台服务启动之后）建三样入口，都指向刚装好的程序：

| 入口 | 位置 | 内容 |
|---|---|---|
| 开始菜单图标 | 所有用户的开始菜单程序目录下的 `澳洲出口客户端.lnk` | 目标是安装目录里的程序，不带参数 |
| 桌面图标 | 公共桌面下的 `澳洲出口客户端.lnk` | 同上 |
| 卸载入口 | `HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall\YuanC` | 名称「澳洲出口客户端」、版本、发布者 YuanC、图标、安装位置、大小；卸载命令是安装目录里的程序加 `--uninstall-prompt`；不提供「修改」和「修复」 |

内容与要写的相同就不重写，重复安装不改变最终状态。快捷方式直接调系统组件读写，不起子进程。哪一样没建成，往标准错误写一句，例如「桌面图标没有建成，重新安装一次可以补上。」（只列没建成的那几样，用顿号隔开），安装仍算成功：有的安全软件会拦桌面图标，不能因此让安装失败。覆盖安装失败、改回旧版时不走这一步，三样入口仍指向旧版。自动更新成功或回退之后，三样入口跟着指到当前在用的那一版，见 [自动更新说明](自动更新说明.md)。

客户双击后点击「安装后台服务(需管理员确认一次)」，界面用 `runas` 拉起自身的安装角色。首次安装只需一次 UAC；以后正常启动界面不弹 UAC。显式修复或卸载仍是管理员动作。所有系统命令用绝对路径、参数列表、隐藏窗口执行；唯一的 ShellExecute 例外是上述提权入口。

### 界面换到安装目录里的那一份

后台服务只接受安装目录（`%ProgramFiles%\YuanC\app`）之下的程序发指令，而客户双击的往往是下载来的文件（放在桌面或下载目录）。因此界面每次初始化先看自己在不在安装目录，不在就换到服务登记的那一份。

| 情形 | 界面的做法 |
|---|---|
| 界面程序已在安装目录 | 照常连后台服务 |
| 不在安装目录，服务登记的程序内容相同 | 启动服务登记的程序并退出本进程 |
| 内容不同，且这个文件的版本号更高 | 显示「可安装新版本」，主按钮「安装这个版本」，安装成功后换过去 |
| 内容不同，且已装的一样新或更新、或版本号认不出 | 直接换到已装的那一份 |
| 服务登记的程序读不到、不在安装目录之下或文件不存在 | 显示「需安装后台服务」 |

安装或修复成功后界面重新初始化，所以首次安装完界面会自动换过去。服务登记的程序取自 `HKLM\SYSTEM\CurrentControlSet\Services\YuanCService` 的 `ImagePath`，只读注册表、不起子进程；内容相同指长度与 SHA256 都相同；版本号按安装目录名比较。交接前先释放 `Local\YuanC-ShowWindow`；新进程隐藏窗口启动、不提权，`--tray` 原样传下去。启动失败留在当前界面，显示「无法打开已安装的客户端」，主按钮可重试。界面在安装目录之外时不会进入可用状态。

覆盖安装：服务原来登记的是另一份程序时，安装在改完配置后先停服务再启动新版。启动后 60 秒内每 2 秒读一次后台状态，读到新版本号的应答才算成功（PR #109，2026-11-28；此前只等 3 秒、看服务是不是「运行中」，后台晚一点才出错的会被当成装好了）。后台要过了数据目录核验、内核文件校验、运行时创建才会开管道，所以读得到状态就是真的起来了。没起来时分三种情况，如实报：

- 旧程序文件还在：先停服务（新版可能进程还在、管道不通），把服务与自启项改回旧版并启动。旧后台起来了，报「新版本的后台服务未能启动，已改回原来的版本。」；旧后台也没起来，报「新版本的后台服务未能启动，已改回原来的版本，但原来的后台服务也没能启动。请重启电脑，或联系管理员。」
- 旧程序文件已经不在：不改回，报「新版本的后台服务未能启动，原来的版本已经不在，没有改回。请重新安装，或联系管理员。」

停服务不撤断网保护。

## 后台与界面分离

仅后台服务创建 ClientRuntime，持有内核、断网保护、凭据及配对存储。后台日志经 RedactingLog 写入滚动的 `%ProgramData%\YuanC\run\service.log`，不记录异常原文、邀请码或配对正文。后台未处理异常以非零状态退出，交给系统失败动作重新启动。

包使用缓存中的 `System.ServiceProcess.ServiceController 10.0.9`。按派单方第一次答复，允许其自动引入 `System.Diagnostics.EventLog 10.0.9` 间接依赖；App/Core 均不直接引用该包、不调用该接口。服务 `AutoLog=false`，不写 Windows 事件日志。

窗口关闭只隐藏到托盘；托盘提供「打开窗口 / 连接 / 断开 / 退出界面(隧道不受影响)」。退出界面、界面异常和界面崩溃均不操作内核或防火墙。第二个界面实例通过 `Local\YuanC-ShowWindow` 命名事件唤起第一个窗口并退出。

服务停止或系统关机时关闭管道、释放运行时，停内核但不主动撤销断网保护。显式断开（包括卸载前发出的断开）走原有撤防流程。再次启动按下文期望状态分路，满足保持条件时不撤防；状态机迁移表及重试退避不变。

服务未安装时提示安装；已安装未运行时提示修复。服务运行但无法连接管道时，每次连接超时 3 秒，初次失败后重试 5 次，间隔 1 秒，最终提示「无法连接后台服务,请重启电脑或联系管理员」。

## 本机管道协议

入口为 `\\.\pipe\YuanC-Control`，最多 16 个并发实例（16 个监听任务），每个连接独立读循环。权限关闭继承：SYSTEM、BUILTIN\Administrators 为 FullControl，BUILTIN\Users 为 ReadWrite，Network SID 明确拒绝 FullControl；不监听 TCP。真实本机与网络身份访问效果仍须真机验收。

防占满与防冒名：

- 首实例独占：服务启动时先同步创建第一个管道实例，带「首实例」标志；若同名管道已被别的程序先建好，创建失败，服务在 `run/service.log` 写「管道名已被其他程序占用，后台服务拒绝启动」后按既有致命退出流程处理，不与冒名者共用名字。之后的实例不带该标志。
- 每进程限连：服务接受连接后先取客户端进程号，每个客户端进程最多同时 2 条连接，总数不超过 16。取不到进程号或超限的连接直接断开、不进入协议处理，日志记一行「同一程序的管道连接数超限，已拒绝（进程 <进程号>）」，同一进程五分钟内只记一次。
- 空闲断开：尚未发送 `subscribe` 的连接，30 秒内没有新请求就由服务端断开；每收到一条请求重新计时，指令执行期间不计时（回完应答后重新开始）。已订阅的连接靠推送保活，不受此限，只由对端关闭或服务停止断开。
- status 不排队：`status` 与 `check_update` 一样不进指令队列，直接读当前快照返回；connect、disconnect、redeem、import_pairing、clear_pairing、set_environment、read_audit、read_selfcheck 仍按到达顺序逐条执行，顺序语义不变。这样长指令执行期间，更新助手探活与界面刷新也能立即拿到状态。
- 调用者核验：服务端取客户端进程的程序完整路径（只查询，不起进程），只有位于 `%ProgramFiles%\YuanC\app` 之下的程序（规范化后严格在该目录之下，不含 `..` 段，不等于该目录本身，比较不分大小写；不看会话号，界面在用户会话、卸载与更新助手在管理员会话都允许）才能执行 connect / disconnect / redeem / import_pairing / clear_pairing / set_environment / set_routing / check_update / read_audit / read_selfcheck，其他程序只能用 status / subscribe。审计含本机其他程序的规则名与完整路径，自检含产品核验到的真实出口地址，检查更新会触发对外网络请求。被拒时返回 `ok=false`、`error=「只有本产品的界面程序可以执行此操作」`，不进指令队列、不改期望状态；连接本身照常保留，status 与 subscribe 可用。取不到程序路径同样按安装目录之外处理。service.log 记一行「来自安装目录之外的程序连接了后台服务，只允许查询（进程 <进程号>）」，同一进程五分钟内不重复；日志写失败不影响监听。

Core 的 ControlServer/ControlClient 只接收 Stream。App 负责创建命名管道。每条消息为 UTF-8 JSON 对象加 `\n`，单行最多 1 MiB（不计终止换行），超限只断开对应连接，未以换行结束的残帧不执行。

请求：`{"id":1,"op":"status"}`。id 为客户端自增整数；op 支持 `status`、`connect`、`disconnect`、`redeem`、`import_pairing`、`clear_pairing`、`read_audit`、`read_selfcheck`、`subscribe`、`check_update`、`set_environment`（附 `enabled` 布尔值，缺失返回「指令缺少 enabled」）。检查更新立即返回当前进度；快照增加 `service_version` 和 `update`，更新状态变化也推送。兑换附 `code`，导入附 `pairing_json`，均为字符串。

应答含同请求 `id`、`ok`，可附 `error`、`snapshot`、`audit`、`self_check`。自检汇总随快照字段 `self_check_status` 搬运，旧消息缺失时默认「未检测」。快照字段为 `state`（既有状态枚举名称）、`status`、`message`、`protection_active`、`mode`。订阅后每次状态变化推送 `{"event":"snapshot","snapshot":{...}}`。未知 op 返回 `ok=false,error="不支持的指令"`；坏 JSON 返回 `id=null,ok=false,error="指令格式错误"`，两者均保持连接。错误不转发异常原文。

`ok` 表示指令处理结果，连接是否建立以快照状态为准。导入在界面读取用户选定文件后传正文，服务校验和保存；导出由界面依次发 read_audit 与 read_selfcheck，服务返回审计或自检全文（不存在为 null），界面把两段原样放入 firewall_audit 与 self_check 字段后写入用户选择的位置。两条只读指令均进入指令信号量，并与改状态指令一样受调用者核验限制，安装目录之外的程序被拒；任一全文编码后超过协议单行上限均返回中文错误，不截断文件。

### 代理范围指令与快照补充

| op / 字段 | 内容与约束 |
|---|---|
| `set_routing` | 改状态指令，沿用安装目录调用者核验与指令串行队列；携带 `mode`（global / apps）和 `apps`（完整程序路径数组）；缺 mode 返回「指令缺少 mode」，缺 apps 按空数组；不改 desired.json |
| `snapshot.routing_mode` | 当前代理范围；旧 JSON 缺字段默认 global |
| `snapshot.routing_apps` | 程序路径数组；旧 JSON 缺字段默认空数组；全部流量仍保留所选名单 |

`set_routing` 与 `set_environment` 一样属于 TrustedOnlyOps（与 check_update / read_audit / read_selfcheck 一样只给安装目录内的程序），不可信调用者被拒，不调用门面。控制器要求已断开、没有保护和没有待恢复记录才保存；连接与恢复模式不一致时拒连。连接中快照取本轮生效范围，已断开时读取设置。界面不乐观修改本地名单，服务返回拒绝时立即重新读取快照，单选按钮和列表回到实际值。完整语义见 [分应用代理说明](分应用代理说明.md)。

## 客户端核验服务端身份

界面、更新助手、卸载三处连上管道后、发第一条指令前，先核验管道服务端进程：必须运行在会话 0（系统服务所在会话），且程序完整路径规范化后位于 `%ProgramFiles%\YuanC\app` 之下（不含 `..` 段，不等于该目录本身，比较不分大小写）。任一步查询失败都按核验不过处理。用于防止服务停止期间别的程序抢建同名管道冒名。

- 界面：核验不过立即断开，状态显示「后台服务身份核验失败」，提示「连接到的不是本产品的后台服务，已断开；请联系管理员。」，不再重试（重试只会再连到同一个冒名者）。
- 更新助手：核验不过与连不上同样处理，由下文服务进程兜底判定是否标坏，见 [自动更新说明](自动更新说明.md)。
- 卸载：核验不过输出「后台服务身份核验失败，按未联系上处理。」，不向对方发任何指令，走下文「服务不可达」路径。

管道消息不做签名或共享密钥鉴权，冒名场景由进程身份核验覆盖。

## 同机其他账户与程序的边界（已知局限）

服务端的调用者核验（见上文「本机管道协议」）只按程序所在目录区分，边界如下：

1. 安装目录 `%ProgramFiles%\YuanC\app` 只有管理员能写，普通用户进程不能把自己放进去，所以换出口（connect、redeem、import_pairing）、撤保护（disconnect、clear_pairing）和修改环境开关（set_environment）只能由本产品程序发起；安装目录之外的程序连上管道只能查状态与订阅；检查更新、读审计、读自检报告同样只给本产品程序。
2. 但同一台电脑上任何能登录的账户都能运行本产品界面，也能用界面自动化（模拟点击）驱动本产品界面——本产品不区分同机账户，这是多用户电脑上的已知局限。需要隔离的场景应给每个账户单独的电脑，或由管理员限制谁能登录。
3. 配对文件目前只做格式校验、没有签名；替换配对文件需要能发 import_pairing（即运行本产品界面）。配对文件签名方案（节点私钥签名、客户端内置公钥校验）待拍板，本期不做。
4. 管理员进程可以做任何事（包括改写安装目录、停服务、改防火墙），不在防护目标内。

## 安全存储与期望状态

安装复制程序之后、配置服务之前，以及修复启动服务之前，核验 `%ProgramData%\YuanC` 根目录和 `run`、`secure`、`updates` 子目录。后台服务每次启动也先核验这些目录，再执行更新恢复和创建运行时。加固时全部断开 ACL 继承，删除原有权限，只保留 SYSTEM 与 BUILTIN\Administrators 两条可由文件和子目录继承的完全控制权限，所有者设为 Administrators；普通用户无任何访问权限。已有 `bin` 目录同样核验，不存在时不主动创建。

核验拒绝目录联接、符号链接等重解析点，所有者必须是 SYSTEM 或 Administrators，不允许其他身份的 Allow 权限，也不允许针对这两类身份的 Deny 权限。不合格目录能修就修，修正一次后重新核验；重解析点或无法修正的目录导致拒绝启动。安装失败提示「数据目录权限设置失败，请以管理员身份重试或联系管理员。」并返回 1；服务写入 `run/service.log`「数据目录权限异常，后台服务拒绝启动：<异常文案>」，随后按既有致命退出流程交由系统失败动作处理。异常文案仅含目录相对名和固定中文原因；即使日志无法写入也必须非零退出。

普通用户不需要读取该数据目录：界面只经本机命名管道与服务通信，导入由界面传入用户选定的文件正文，导出审计由服务经管道返回后写入用户选定位置。后台的刷新凭据、配对文件、设备标识分别存为 `secure/credential.bin`、`secure/pairing.bin`、`secure/device-id`，使用 LocalMachine DPAPI；机器范围加密必须结合目录权限，不能单靠 DPAPI 隔离本机用户。

读取 `server.json` 前核验文件所有者须为 SYSTEM 或 Administrators；`server_url` 必须使用 IPv4 数字地址的 HTTPS 地址，不使用域名或 IPv6。配置中的 `sing_box_path` 必须是 `%ProgramFiles%\YuanC` 安装目录下的绝对路径，禁止 `..` 路径段。未提供该字段时仍使用内嵌内核。观察项：本次不处理安装前已放入 `run`、`secure` 等目录的旧文件内容，也不删除或重加密密文，历史内容的可信性仍需另行评估。

不做 `%LOCALAPPDATA%`、CurrentUser DPAPI 旧数据迁移：产品尚未交付客户。Core 旧调用默认保持原有用户目录及存储行为；仅服务明确传 secure 根目录和 LocalMachine scope。原有默认设备标识文本格式保留，服务使用加密格式。明文运行配置和防火墙审计所在的 `run` 目录纳入同等加固；期望状态的写入方式不变，启动按下述规则分路。

`%ProgramData%\YuanC\run\desired.json` 示例：`{"connect":false,"updated_at":"2026-10-22T00:00:00.0000000+00:00"}`。通过 `.tmp` 写入、刷盘后原子覆盖。显式连接处理后写 true，显式断开处理后写 false。启动先完成数据目录核验与更新恢复，再读取期望状态，之后才创建运行时。期望不是 false 且有恢复记录、有配对或鉴权凭据时，保持保护直接重连，不先恢复网络；false 时恢复网络并发布状态，不自动连接。文件缺失或解析失败返回 null，按不是 false 处理。有恢复记录但找不到配对文件、登录凭据或服务器配置时，保护保持并停在「需人工处理」，用户点「断开」才恢复网络，详见 [服务重启时保持保护](断网保护加固说明.md#服务重启时保持保护)；没有恢复记录时恢复入口不操作防火墙，再按既有条件自动连接。非保持分支在防火墙恢复之后还会按网卡记录 `nic-guard-state.json` 恢复连接期间关掉的网卡 IPv6 绑定（保持保护的分支不恢复，真机待验证），详见 [网卡公网地址收紧](断网保护加固说明.md#网卡公网地址收紧)。关闭窗口、退出界面、停止服务不会修改期望状态。

保持保护启动后，分发版直接重新鉴权，自用版使用配对会话；成功后重新套用规则，再启动隧道。鉴权网络错误按既有退避重试，界面先显示重连中，耗尽转需人工处理，保护全程保持。用户可点「连接」重试，要恢复普通网络必须点断开。分发版的 `YuanC-KS-Auth` 仅放行服务进程到配置的鉴权服务器 IPv4:端口，只允许 TCP；自用模式不加这条规则，不放行系统 DNS。两层降级恢复只用于恢复路径，详见 [服务重启时保持保护](断网保护加固说明.md#服务重启时保持保护)。

## 内核跟着后台服务走

连接内核 sing-box 由后台服务作为子进程启动，原来没有任何东西把它绑在服务上：服务崩溃或被强行结束后，内核与虚拟网卡会继续接管全机流量，服务被系统自动拉起后又起一个新内核，两个抢同一块虚拟网卡。现在分三层处理。

1. 作业对象「关闭即结束」：启动内核后把它放进一个作业对象，并设置「最后一个句柄关闭时结束作业内所有进程」。后台服务进程一没，系统随之结束内核。创建作业时安全属性传空、名字传空，句柄不可继承。句柄一旦可继承，内核经重定向输出继承句柄后会自己攥着作业，服务死了作业也不关，这一层就失效。
2. 启动时与每次起内核前清残留：后台服务启动时先结束本产品残留的内核进程，每次启动内核前再结束一次。只认本产品的内核：映像全路径与要启动的 `sing-box.exe` 完全相同，或位于 `%ProgramData%\YuanC\bin` 之下各版本目录里的 `sing-box.exe`；其他路径下同名的程序一个都不动。结束成功记一行「已结束上次残留的连接内核 N 个。」。绑定作业失败时记「连接内核未能绑定到后台服务，后台服务意外退出时它可能残留。」，进程照常使用，由清理兜底。真有残留结束不掉时报「上次残留的连接内核没能结束，请重启电脑后再连接。」，本次不启动新内核。
3. 就绪判断认本次启动的进程：启动前如果旧网卡还在线，最多等 5 秒等它下线；等不到就继续启动新内核，但此时必须看到新内核连续稳定 2 秒（每 250 毫秒看一次）在线才算连上，避免把旧内核留下的网卡当成新内核已就绪。新内核的虚拟网卡最多等 30 秒（2026-10-28 本机实测，旧网卡刚删掉后的首次启动有两次约 20 秒才建好），内核中途退出立即判失败，不用等满。

起进程与绑定作业之间有一个极小的瞬间：如果后台服务恰好在这一瞬死掉，内核可能来不及进作业。这个窗口由下次启动时的清理兜底。

以上均为代码与自动测试覆盖的行为，真机未测。

## 卸载

由管理员运行已安装程序的 `--uninstall`。先尝试连接管道（3 秒）并核验服务端身份：

- 连上且核验通过：发送 disconnect；结果不是「保护已撤销且已断开」时报「未能撤销断网保护，卸载已停止，请联系管理员。」，不假装卸载成功。撤防成功后停止服务（最多等待 30 秒）；断开消息里带着恢复记录不见了的警告时，同样把它打到标准错误。
- 连不上或核验不过（例如管道被占满、被冒名）：输出「无法联系后台服务，将在停止服务后直接恢复网络。」，先停止服务（避免它再改规则），再由卸载程序自己删除本产品的断网保护规则、按恢复记录还原三个配置档的默认出站策略；没有恢复记录时，只在本产品全局模式规则还在时把设成阻止的配置档改回允许，并把警告打到标准错误，见[没有恢复记录时点断开](断网保护加固说明.md#没有恢复记录时点断开)。这一步失败时报「未能撤销断网保护，卸载已停止，请联系管理员。」，并保留服务与登录自启值——服务留着，下次开机仍能按期望状态接管保护，比留一套没人管的阻止规则安全。服务本身不存在时同样执行这一步，清理可能残留的规则。

上述成功后删除服务、删除登录自启值，再删开始菜单图标、桌面图标和卸载入口。这三样里哪一样没删掉，往标准错误写一句，例如「桌面图标没有删掉，可以手动删除。」，卸载仍算成功。重复卸载能处理服务、自启值或这三样已不存在的情况。

### 从系统「应用和功能」卸载

系统运行卸载入口登记的命令，即安装目录里的程序加 `--uninstall-prompt`：

1. 弹确认框「确定卸载澳洲出口客户端吗？卸载会断开连接并撤掉断网保护，电脑恢复原来的网络。配对文件和日志会保留。」，默认选「否」。选「否」直接结束，什么都不动。
2. 选「是」：当前已是管理员，就在本进程里做上面的卸载动作；不是管理员，用 `runas` 拉起自身的 `--uninstall`，弹一次管理员确认。
3. 卸载成功：结束还开着的本产品界面进程（只认安装目录里的程序，安装目录之外的同名程序不动），弹「已卸载。配对文件和日志还留在电脑上，重新安装后可以接着用。」。
4. 卸载没成功（含用户取消管理员确认、断网保护没能撤销）：弹「卸载没有完成。请再试一次，或联系管理员。」，返回 1；服务、自启值和三样入口都还在，可以再点一次。

保留 `%ProgramData%\YuanC`，其中包含凭据、配对文件、日志、期望状态和恢复记录；如需手动清理，先由管理员确认服务已卸载、网络已恢复，再删除该产品目录。程序版本目录也不自动清理。
