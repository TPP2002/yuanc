# Windows 薄客户端骨架

## 三项目职责

- WinClient.Core：net9.0 类库，无 WPF 引用。承担鉴权通信、状态机、连接流程、进程管理、配置渲染、防火墙计划与执行、日志脱敏和凭据存储。
- WinClient.App：net9.0-windows WPF。只负责窗口、绑定、用户输入、导出文件位置选择和单实例入口；业务由 Core 执行。同一个 exe 分界面、后台服务和安装角色；界面清单为 asInvoker，声明 Windows 10/11 兼容。只有后台服务持有业务运行时，界面通过本机管道操作。
- WinClient.Tests：xunit，使用可注入的 HTTP、进程与命令执行替身；不启动真实隧道或修改主机防火墙。

NuGet.Config 使用 nuget.org 源。包精确固定为 Microsoft.NET.Test.Sdk 17.12.0、xunit 2.9.2、xunit.runner.visualstudio 2.8.2；另按第一次岔路答复，仅 Core 引用 System.Security.Cryptography.ProtectedData 10.0.11，用于 DpapiCredentialStore。JSON 使用框架自带实现。

App 的 SingleFile 发布配置指定 win-x64、单文件、自包含和原生库自解包；普通 build/test 不启用发布配置。当前已内嵌内核并支持后台服务化、自用模式自动更新；仍不做 Windows 代码签名或安装向导。更新使用独立的清单签名，不等同于 Windows 发布者证书签名。

Core/Update 负责版本、清单、签名、下载、恢复记录、目录计划和调度；只依赖框架 API。协议层合成服务版本与更新状态，不修改连接快照。App 更新助手执行系统服务切换、命名管道健康检查和注册表更新；启动恢复先于运行时创建。详细流程与未执行的真机项见 [自动更新说明](自动更新说明.md)。

断网保护在连接时把其他程序自带的出站放行规则临时停用、断开时恢复,并把组策略规则只记入审计;停用范围、记录顺序与恢复失败的处理见 [断网保护加固说明](断网保护加固说明.md)。

连接时还会记录并强制开启三个防火墙配置档，核对实际生效值后才允许连接，失败明确拒连、断开按记录还原启用状态；详见 [防火墙配置档被关闭或被策略覆盖](断网保护加固说明.md#防火墙配置档被关闭或被策略覆盖)。

## 配置与启动

产品目录为 `%ProgramData%\YuanC`。管理员提供 `server.json`，文件所有者须为系统或管理员；字段 `server_url` 为真实鉴权 HTTPS 地址，主机只认 IPv4 数字地址，不使用域名或 IPv6。`sing_box_path` 必须位于 `%ProgramFiles%\YuanC` 安装目录之下，且为不含 `..` 路径段的绝对路径；仓库不提供节点地址、令牌、UUID、密码的默认值或有效示例。文件缺失时显示“未配置服务器”。

后台服务启动在数据目录核验与更新恢复之后，先读取期望状态，再创建运行时。期望不是 false（含缺失或损坏）时，运行时跳过启动恢复，读取配置与会话来源；控制器在有恢复记录且有配对或鉴权凭据时保持保护直接连接。分发版重新鉴权，自用版使用配对会话，成功后重新套用规则再启动内核；网络错误按既有退避重试，重连中及耗尽后的需人工处理状态均保持保护，用户要恢复普通网络必须点断开，也可点连接重试。期望为 false 时先恢复网络、不自动连接；没有配对／凭据或服务器配置时由控制器走既有恢复路径；无恢复记录时恢复入口不操作防火墙，再按原条件自动连接。界面不读取服务器配置。两层降级恢复只在恢复路径发生，见 [启动恢复失败的降级处理](断网保护加固说明.md#启动恢复失败的降级处理)。不复用磁盘上的旧隧道配置作为授权依据。邀请码兑换保存新的刷新令牌，用户随后点击连接。会话和账号任一个到期都停止内核、进入需重新登录，保持已有保护。

**会话续期（邀请码模式，SEC-AUTH-SESSION-EXPIRY-LOCK-1022）**：连接期间在会话有效期（会话与账号到期取早者）走到八成时，控制器自动向鉴权服务器续期，用刷新令牌换一份新会话。两种代理范围下，sing-box 都把「服务进程 + 节点地址/32 + 鉴权端口」交给 direct 出站，配合防火墙 YuanC-KS-Auth 窄规则放行（见 [断网保护加固说明](断网保护加固说明.md)），续期从物理网卡直出、不经隧道、不依赖路由器 NAT 回环。自用版没有鉴权端点，不加这条规则。新会话只换了令牌与到期时间、节点与内核配置内容不变时只换会话、不重启隧道，也不动防火墙和提示；节点地址、端口或凭据等内容变了，按既有刷新路径在保护下重启（地址变化先替换节点放行规则，再停内核按退避重启）。网络、限速、异常响应等网络类失败时隧道照常，每五分钟重试一次，直到到期前一分钟为止，之后交给到期定时器按既有逻辑进需重新登录；无效令牌、账号到期、邀请码不存在等凭据类拒绝按既有规则进需重新登录，停用、吊销、设备上限按既有规则进需人工处理，均停内核、保护保持。剩余不足一分钟时不再安排续期。自用模式不续期（配对会话固定远期）。断开、重连或更换来源后，旧的续期回调随既有定时器代数作废。状态机不改，不新增事件。公开的手动刷新入口在内容没变时同样只换会话、不重启隧道。

真机待验证（续期）：路由器关闭 NAT 回环（或抓包确认续期流量从物理网卡直出）时，分发版全部流量模式连接满会话有效期八成自动续期成功、上网不中断；六小时真实到期前自动续期一次且上网不中断；鉴权服务器关机时续期失败、隧道照常直到到期进需重新登录；续期时服务端换了节点地址，规则与内核在保护下切换。

服务设备标识为首次生成的随机标识，不采集硬件序列号。服务的设备标识、刷新令牌和配对文件使用 DPAPI LocalMachine，存于 `%ProgramData%\YuanC\secure`，目录只允许 SYSTEM 与管理员访问。旧调用默认用户目录行为仅用于兼容既有调用与测试；不迁移旧用户数据。内存实现供测试注入。

## 自用模式与配对文件（WINCLIENT-LOCAL-MODE-1024）

主界面提供“导入配对文件”、当前模式与次要位置的“清除配对文件”。导入仅接受文件选择框中的 `.ycpair`，支持 `ycpair/1`、`ycpair/2` 和 `ycpair/3`。原八个节点字段的校验保持：四段规范 IPv4 数字地址、两项 1～65535 的端口、43 位 base64url 公钥、2～16 位十六进制短标识、UUIDv4、非空密码及连接校验名称。错误以不含凭据的中文原因提示。设备名优先显示 `device_name`，没有时显示 `exported_at`。导入成功不自动连接，提示用户点击连接；保存过配对文件且期望状态不是 false 时，后台服务下次启动会使用本地会话连接。

`ycpair/2` 的 `node` 为十键：`host`、`reality_port`、`hy2_port`、`sni`、`reality_public_key`、`short_id`、`uuid`、`hy2_password`、`hy2_server_name`、`hy2_certificate`。`ycpair/3` 的 `node` 与鉴权会话的 `node` 均为十一键：上述十键加节点级备用通道混淆密码 `hy2_obfs_password`（`NodeInfo.Hy2ObfsPassword`，缺省空串）。`ycpair/3` 必须同时满足 `ycpair/2` 的备用线路校验，且 `hy2_obfs_password` 必须存在、为字符串并匹配 `[A-Za-z0-9_-]{16,128}`，否则提示“备用线路混淆密码格式不正确，请重新导出。”；`ycpair/1`、`ycpair/2` 里若出现该键也按同一规则校验。鉴权会话里该字段可能为空串（鉴权服务器未配置混淆密码副本），此时不加混淆。混淆密码非空时，`LocalConfigRenderer` 在备用出站 `password` 之后、`tls` 之前写 `"obfs": {"type": "salamander", "password": <密码>}`，与节点 `client_config.py` 同形；为空时不写 `obfs` 键。新增名称必须是合法主机名；证书必须为逐行非空字符串数组，首尾分别为 `-----BEGIN CERTIFICATE-----` 和 `-----END CERTIFICATE-----`。备用通道独立使用该名称和证书渲染 `tls.server_name`、`tls.certificate`，不使用主通道的 `sni`。名称必须与证书 SAN 匹配，不能关闭证书校验。

没有这两个新字段的 `ycpair/1` 保持原渲染：备用名称为 `exitnode`，不写 `certificate`。`PairingFile.Warning` 保存旧版提示，导入界面消息包含“配对文件是旧版,备用线路可能不可用,建议在小主机上重新导出”。`ycpair/2` 的提示为“配对文件是旧版,没有备用线路混淆参数;节点已启用混淆时备用线路不可用,建议在小主机上重新导出”，渲染不带 `obfs`；`ycpair/3` 没有提示。节点启用混淆后旧 `ycpair/2` 文件主通道照常、备用线路不可用，须在小主机上重新导出。改了节点的 `hy2_server_name` 要重新生成证书并重新导出配对文件；安装清单已完成时，简单重复安装不会替换证书。

服务侧 `PairingStore` 将完整配对原文（包括未知扩展字段）用 DPAPI LocalMachine 加密，原子保存到 `%ProgramData%\YuanC\secure\pairing.bin`，临时文件也是密文。导入时不另存 `.ycpair` 原文；加解密字节缓冲用后清零。清除仅删除客户端的密文副本，不删除用户选择的原始文件，也不吊销节点设备。导入与清除在连接控制器串行锁内提交；连接中或保护未撤销时要求先主动断开，不能借更换模式绕过断网保护。

会话入口统一为 `ISessionSource`。`AuthServerSessionSource` 保持邀请码兑换、刷新凭据与服务器会话流程；`PairingSessionSource` 不调用鉴权服务，直接返回本地节点、空会话令牌和固定远期有效期。启动选择优先级为配对文件、服务器配置、未配置；有配对文件时不会创建鉴权客户端。清除配对后有服务器配置则回到邀请码模式，否则回到未配置。连接内核路径继续取既有服务器配置中的路径，未指定路径时使用内嵌内核，幂等解包到 `%ProgramData%\YuanC\bin\<内核版本>`，不在运行时下载。

本地渲染口径取自节点仓 `node/exitnode/proxy/client_config.py`。分发模式的会话同样只用 `node` 本地渲染，服务器不再下发连接配置（旧服务返回的 `singbox_config` 忽略），两种模式都走同一个 `LocalConfigRenderer`。测试直接读取节点黄金输入与 `node/tests/golden/proxy/client-windows.json`，按节点测试惯例仅为实际结果添加测试用 `_comment` 后，比较完整 JSON 字段和值，字段顺序不作要求；没有另外复制一份黄金配置。`TunnelTransport.RenderConfiguration` 继续补固定网卡名称。主通道、备用通道、隧道内域名解析、IPv6 阻断和无直连出口均保留。断网保护的节点 TCP 端口取配对数据，既有调用默认仍为 443；放行规则数量、程序与节点地址限制不变。

两种来源随后共用状态机、断网保护和内核启动路径，迁移表与退避常数不改。远期会话到期等待分成不超过一天的可取消等待，避免系统定时器无法接受数千年时长。自用模式连续重连耗尽进入需人工处理时显示“连不上澳洲出口，出口地址可能已变，请在小主机上重新导出配对文件再导入”，保护仍保留；其他操作错误仍显示原来的具体错误，不把缺内核等问题伪装成地址变化。

按派单方第一次岔路答复：运行配置与服务器模式同样以明文写在 ProgramData 下，仅管理员可读；收紧（启动后删除或更严 ACL）属后续加固，不在原自用模式施工单。这里的“仅管理员可读”原为部署权限要求，写入代码继承目录权限，不能仅凭编译测试证明部署环境满足这一要求。配置仍只有既有 `run/config.json` 及原子写入临时文件，不新增运行配置副本或清理逻辑。配对原文加密保存与运行配置明文保存是两个不同边界。2026-10-22 起目录 ACL 由安装与启动核验，见 [服务化与自启说明](服务化与自启说明.md)。

配对会话向 `RedactingLog` 登记设备标识与密码，混淆密码非空时一并登记；实际内核日志继续使用既有递归秘密登记与脱敏流程（`SingBoxProcessManager` 递归登记所有名称含 `password` 的字符串字段，已覆盖 `outbounds[*].obfs.password`，未改动）。测试用 HTTP 桩断言配对连接、刷新、断开及误点兑换均不发鉴权请求；这不表示隧道内核无需访问澳洲节点、隧道内域名解析或原有连通性探测地址。自动测试仍不能替代真实设备上的连接、防火墙和权限验收。

## 状态机（文字图，既有流程）

Disconnected --UserConnect--> Connecting --SessionOk--> 安装保护并启动内核 --TunnelUp--> Connected。

Connecting/Connected --TunnelDown--> Reconnecting --BackoffElapsed--> 再启动内核；未取得有效会话时只重新鉴权，不启动内核。

退避依次为 2、4、8、16、32、60 秒；其后继续按 60 秒，累计六次 60 秒尝试失败进入 NeedsManual。成功连接清零计数；重复的退出通知不会额外消耗次数。

SessionExpired、无效令牌、账号到期进入 NeedsLogin；停用、吊销、设备上限和不可恢复操作错误进入 NeedsManual。网络错误和限速有限重试。所有这些迁移不产生 RemoveKillSwitch。

UserDisconnect 是正常连接流程中唯一产生 RemoveKillSwitch 的事件：先停内核，成功后撤本项目规则并恢复原出站策略。关闭窗口隐藏到托盘，退出界面不影响后台连接；停止后台服务只停内核而不主动撤防，下次服务启动按期望状态与配对／凭据分路，满足保持条件时直接重连，不恢复遗留保护。

NodeChanged 产生 UpdateKillSwitchNode(oldIps,newIps)，只替换 `YuanC-KS-Node-*`，不修改默认策略或其他类别的规则；会话刷新后内核在现有保护下重新启动，应用新的凭据和配置。

## 防火墙计划与恢复

按第二、三次岔路答复，执行后端为 PowerShell NetSecurity，替代原 netsh 方案。Plan 为纯函数，输出 SetProfileDefault、AddRule、RemoveRulesByPrefix、RestoreProfileDefault、Audit。ToPowerShellScript 使用单引号字面量转义，执行器使用 ArgumentList、不经 shell，设置 CreateNoWindow=true 和 UseShellExecute=false。

Apply 在任何系统修改之前，将 Domain/Private/Public 的原 DefaultOutboundAction 写入 `run\killswitch-state.json`；重复 Apply 不覆盖原始值。先把三个 profile 的默认出站设为 Block，然后创建项目放行规则，全部成功后标记 applied=true。

本项目原有五条放行规则为：内核到节点 IPv4 的 TCP 端口（默认 443）、内核到节点的 Hysteria2 UDP 端口、指定 TUN 别名上的出站、IPv4/IPv6 回环、DHCP 客户端 UDP 68 到服务端 UDP 67。分发版在两条节点规则之后、TUN 之前追加 `YuanC-KS-Auth`，只允许当前服务进程到配置的鉴权服务器 IPv4:端口的 TCP 出站，防止默认出站阻止时无法重新鉴权。自用模式仍只有原五条规则。DNS 无单独直连放行。

配置渲染固定 TUN 名称 YuanC-TUN，并设置 auto_route=true、strict_route=true；不改动服务器原始 JSON 对象。网卡规则按固定别名创建，不以前置查询要求网卡已存在。实际 Windows 版本上的别名创建行为须由后续真机验证确认，失败会明确转人工处理，不回落。

重连不撤规则，是为了避免内核停机期间恢复普通默认出站。节点变化仅删除旧的 Node 前缀规则、增加新规则，期间默认出站始终保持 Block。

Remove 仅删除 YuanC-KS- 前缀规则（包含 Auth），按恢复文件逐一恢复三个 profile；按派单方明确要求，无恢复文件时设回 Allow。启动进入恢复路径时，对 applied=true 以及中途失败留下的 applied=false 文件均尝试恢复；保持保护路径不调用 RecoverAsync 或 RemoveAsync。失败保留恢复文件，不把部分成功报告为成功；恢复规则名单的行为见 [断网保护加固说明](断网保护加固说明.md)。

## 环境一致性

后台服务在隧道就绪后按默认开启的总开关切换澳洲时区、关闭自动时区，并设置 Chrome / Edge 的首选语言、WebRTC 与禁定位策略。修改前原子保存原值，主动断开先恢复网络再恢复环境，服务重启沿用保持保护与恢复分路。环境失败只更新提示，不停止隧道、不改变连接状态、不撤断网保护。策略影响所有本机账户和浏览器配置档，不改显示语言或深层指纹，完整范围、恢复机制与真机清单见 [环境一致性说明](环境一致性说明.md)。

## 已知局限

代理范围新增「仅指定程序」，默认仍为全部流量。完整路径同时用于 sing-box 的 process_path_regex 和防火墙 Program，其他程序使用 direct 出站、不受逐程序断网保护；DNS 仍全机经隧道、环境策略仍作用整机。异名联网子进程不继承父进程名单，漏选会直连，同账号可能出现两地并发。无法识别进程的流也可能由内核 direct 出站直连。后台服务自动走隧道，但分发版鉴权直连，服务进程不自动加入阻断名单；出口核验只证明该服务进程的出口，查不出漏选程序。完整边界、配置与真机待验证项见 [分应用代理说明](分应用代理说明.md)。下述既有默认出站阻断和停用其他允许规则的描述适用于全部流量模式。

连接期间巡检把「连接那一刻」的核查延伸到「连接期间每 60 秒」：重新收紧配置档、停用恢复名单之外的新出站允许规则、发现缺失项目规则后幂等重建，并检查防火墙服务。组策略与第三方接管仍是局限，巡检不能证明两轮之间绝无泄漏；异常只告警并续巡，不自动断开、不自动撤保护，详见 [连接期间巡检](断网保护加固说明.md#连接期间巡检)。

**本单不承诺对所有程序零泄漏。** Windows 既有的显式出站放行规则优先于默认出站阻断。带自身放行规则的程序，在隧道断开后可能直连；这是派单方第三次答复明确接受的局限。隧道正常运行时，配置启用 sing-box 的 strict_route 作为路由层保护，但不能据此声称已经通过真机零泄漏验证。

默认出站阻断与项目放行规则仍按前述方案执行；非项目出站允许规则按加固说明临时停用并保留恢复名单，不删除规则、不改入站。不可由本地管理的允许规则仍可能导致直连，不能把自动测试通过视为零泄漏证明。[系统过滤层第二道闸](断网保护加固说明.md#系统过滤层第二道闸wfp)已实施，与原防火墙并存，真机未测，持久性与已知局限见该节。

Audit 只读查询当前启用的非 YuanC-KS- 出站 Allow 规则，保存名称和程序路径到 `run\firewall-audit.json`。诊断按钮合并导出防火墙审计与环境自检报告；完整诊断包、日志打包等仍是后续功能。此审计不自动修复规则。

“已连接”表示内核启动且指定 TUN 网卡已就绪；出口核验结果单独显示，核验中、已核验、不一致或无法核验均不改变连接状态。连续 3 轮无法核验（约 10 分钟）时主消息槽显示提示（自用版提醒可能要重新导出配对文件，分发版提醒检查网络或联系管理员），连接与断网保护保持；重新核验成功后提示自动撤回。地址一致只表示本次取到的出口与配置节点一致，不能独立证明澳洲地理位置或家庭宽带属性。测试替身及编译通过不能替代 Win10/Win11 实机上的 UAC、TUN、DNS/IPv6、进程崩溃与抓包验证。

## 日志与生命周期

配置原子写到 `run\config.json`，内核路径可配置，缺失给出中文提示。stdout/stderr 经敏感字段及已登记秘密值脱敏后写入滚动日志，默认每份 1 MiB、保留三个旧文件；HTTP 不记录请求体、响应体或异常原文。所有子进程均隐藏窗口。

连接控制器串行处理操作，主动断开取消重试和到期定时器；过期的回调不启动新隧道。进程意外退出上报 TunnelDown，主动停止抑制相应崩溃事件。防火墙命令失败、恢复失败不能被界面当作连接成功。

## 验证与交付边界

环境自检在每次出口核验终局后只读评估十项，界面显示汇总并将 `run/selfcheck.json` 与防火墙审计一起导出；只报告、不修复、不断开、不撤保护，真机时序、时区变化、关闭总开关和导出双段内容仍待验证，详见 [环境一致性说明](环境一致性说明.md#环境自检)。

环境一致性真机待验证：切换与恢复时区、自动时区开关、两种浏览器的三项策略、首选语言、连接中总开关、服务重启保持，以及组策略锁定时只告警而连接照常；详见 [环境一致性说明](环境一致性说明.md#真机待验证清单)。

出口 IP 核验：连上后经隧道取真实出口与节点地址比对，结果显示在界面；真机待验证。首次等待 3 秒，单次请求超时 5 秒，无结果每 5 秒重试、累计最多 5 次，每个终局后 5 分钟再查。核验与断网保护巡检都由后台服务执行，界面只接收快照；不增加日志中的地址或响应正文。

真机待验证清单：出口核验一致／不一致／无法核验三种界面；新建出站允许规则 60 秒内被停用并进入恢复名单；配置档改回允许后 60 秒内重新收紧；停掉 MpsSvc 后红字提示而隧道不断。这些项目本次均未执行，完整步骤见加固说明。

真机待验证：自用版把节点公网地址改掉（或在路由器上换掉映射）后，客户端约 10 分钟内出现提醒重新导出配对文件的提示、不断开、断网保护不撤；恢复地址后提示消失。本单未执行真机验证。

自动测试覆盖状态码映射、接口序列化、日志脱敏、状态迁移和退避上限、仅主动断开撤防、节点替换不恢复默认策略、规则白名单、脚本生成和隐藏进程参数、原子配置、凭据往返与启动恢复接线。所有执行通过派单方自测邮箱申请；实际运行结论以邮箱响应和派单方最终复核为准。

当前已实施 Windows 后台服务、安装动作、登录托盘自启、内嵌内核及自用模式自动更新。仍不实施完整诊断包、运行时内核下载、安装向导或 Windows 代码签名。没有执行实际防火墙变更或真实隧道连接，不声称这些实机项已通过。
