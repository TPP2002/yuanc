# 泄漏检测说明

## 用途

真机验收要证明:**连接期间,物理网卡上除了发往澳洲节点(与分发版鉴权服务器)的流量外,没有任何发往公网的包。** 以前只能人工抓包,现在客户端自带一键检测命令 `--leak-check`:用 Windows 自带的 pktmon 只抓网卡、解析抓包文件、按程序归类,输出中文结论与 JSON 报告。

## 命令写法

以管理员身份打开命令行(不是管理员会提示「请以管理员身份运行」并返回 2),在客户端安装目录运行(exe 名以发布说明为准):

```
"YuanC 客户端.exe" --leak-check --seconds 120
```

| 参数 | 含义 |
| --- | --- |
| `--seconds <10~600>` | 抓包时长,默认 120 |
| `--node <IPv4>` | 节点地址(可选)。不给则取隧道内核 sing-box.exe 已建立连接的对端 IPv4;取不到就无法检测,提示「未找到隧道内核的连接，请先连接，或用 --node 指定节点地址」 |
| `--out <目录>` | 输出目录,默认 `%ProgramData%\YuanC\leakcheck\<yyyyMMdd-HHmmss>` |
| `--keep-capture` | 保留抓包文件(capture.etl 与 capture.pcapng),默认检测后删除 |

代理范围(全部流量 / 仅指定程序)与程序名单读自客户端当前设置;分发版鉴权地址读自客户端服务器配置,读不到则不放行任何鉴权地址。

检测流程:依次执行 `pktmon filter remove`、`pktmon start --capture --comp nics --file-name <etl>`、等待指定秒数(期间每 500 毫秒采样一次连接表)、`pktmon stop`、`pktmon etl2pcap <etl> --out <pcapng>`,再解析与归类。只要 start 成功过,就保证执行一次 stop。所有子进程都隐藏窗口。

## 判定规则

- 抓包范围是物理网卡层(`--comp nics`)。
- 任一端在隧道网段 172.19.0.0/30 或 fdfe:dcba:9876::/126 的包属于隧道网卡内部,跳过。
- 对端 = 两端里不属于本机网卡地址的那个。对端是公网地址、不是节点地址、也不是鉴权服务器(地址 + 端口,仅 TCP)→ 记为可疑。局域网、保留网段、组播等不算公网。
- 可疑包按(协议、对端地址、对端端口、归属程序)聚合计数。归属程序靠连接表采样得到。
- 仅指定程序模式下,每条可疑流另标:归属程序路径(不分大小写)等于名单之一,或位于名单某程序所在目录(含子目录)之下 → 「名单程序」;否则 →「名单外程序(按设计直连)」;归属未知 →「归属未知」。
- 解析不了的包计入「未解析」。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 未发现可疑流量(仅指定程序模式:没有「名单程序」或「归属未知」的可疑流) |
| 1 | 发现可疑流量 |
| 2 | 无法检测(不是管理员、pktmon 步骤失败、找不到节点、抓包文件格式不正确等,原因见输出) |

## 报告字段

输出目录下 `leak-report.json`(snake_case):

- `started_at`:开始时间;`seconds`:抓包秒数;`mode`:`global` 或 `apps`。
- `total` 总包数、`tunnel` 隧道内、`allowed` 放行、`unparsed` 未解析。
- `suspicious`:数组,每项含 `protocol`、`remote`(对端地址)、`remote_port`、`process`(归属程序路径,未知为 null)、`listed`(仅指定程序模式:true / false / null)、`count`。
- `verdict`:`clean` / `suspicious` / `unavailable`;`reason`:中文说明。

终端摘要列出前 20 条可疑流:协议、对端地址:端口、程序文件名、计数,仅指定程序模式另标名单状态。

## 隐私说明

- 报告、终端摘要、日志与异常信息都不写本机任何网卡地址,只写对端地址。
- 默认检测结束后删除抓包文件;只有加 `--keep-capture` 才保留。抓包文件含本机地址与对端地址,保留的文件不要外传、不要提交进仓库。

## 建议的真机检测步骤

1. **全部流量模式**:连上后开桌面应用与浏览器,打开 WebRTC 检测页与 DNS 检测页,用管理员命令行运行检测,检测期间正常使用两分钟。期望退出码 0。
2. **仅指定程序模式**:同上,并查看「名单程序」一栏应为零;名单外程序的直连按设计允许。
3. **断开后再测**:断开隧道内核后再检测一次(此时需用 `--node` 指定节点地址),应只剩被阻断的尝试、没有成功外发。

## 局限

- pktmon 需要 Windows 10 2004 及以上版本。
- 只能看到物理网卡层,看不到网卡之上或之下的其他环节。
- 归属靠连接表每 500 毫秒采样,极短的连接可能采不到,显示为「归属未知」。
