# Windows 客户端打包与发布

交付物是 Windows x64 单文件自包含程序，内含连接内核与网卡组件。目标为 Windows 10 1809+、Windows 11；客户不必另装 .NET。同一个程序支持后台服务、托盘界面和自用模式自动更新；没有安装向导或 Windows 代码签名。本说明替代架构说明中关于“本单不内嵌内核”和默认手工放置内核的历史描述；原有网络状态机与保护边界不变，权限改为普通用户界面加 LocalSystem 后台服务。

## 维护人员出包

准备 Windows、.NET 9 SDK、PowerShell 5.1，以及仓库 NuGet.Config 指定的已有包缓存。依赖不足时交维护负责人处理，不在施工工位安装依赖。所有构建和验证仍遵循仓库调度规则。

在仓库根执行一次：

```powershell
powershell -NoProfile -NonInteractive -WindowStyle Hidden -ExecutionPolicy Bypass -File scripts/release/build-winclient.ps1
```

产品默认版本唯一写在 `winclient/Directory.Build.props` 的 `Version`。可传 `-Version <版本号>` 临时覆盖本次发布的程序集与文件名，不修改默认版本文件。

脚本执行 `dotnet publish winclient/WinClient.App -c Release -p:PublishProfile=SingleFile`，指定输出目录与版本；子进程不弹窗口。发布目录为 `build/winclient/publish/WinClient.App/release_win-x64/`，检查其中只有 exe 和 pdb，且客户端 exe 不超过 1 GiB；任一检查失败就退出，不报发布成功。安装包大小不设硬上限（负责人 2026-11-27 定）；1 GiB 是防呆线，与客户端自动更新接收的最大更新包（`UpdateManifest.MaxPayloadBytes`）同数，只为不让坏掉的下载无限写盘。

单文件发布开启了包内压缩（`EnableCompressionInSingleFile`）：内核升到 1.13.21 后不压缩的 exe 为 216,888,912 字节，当时超过了旧的 200 MiB 上限。上限放开后继续开着压缩，是为了包小：更新包要经中国到澳洲的线路下载，整体超时二十分钟，87 MB 比 207 MB 更容易下完。压缩后程序启动时在内存里解开，不改安装目录和解包位置；若真机上内存占用成问题，删掉工程文件里这一项设置即可回到不压缩。

开发机实测（2026-11-27，各两次）：exe 从 216,888,912 字节降到 90,890,440 字节；界面出窗用时 1.3~1.7 秒对 1.5~1.7 秒，没有可见差别；界面进程占用内存从约 120 MB 涨到约 300 MB（工作集），私有内存从约 70 MB 涨到约 145 MB。后台服务进程的内存变化没有量（开发机不装服务），记为真机待验证。若以后要压低内存，另一条路是只压缩内嵌的内核资源并改解包代码，包约 189 MB，离上限只剩约 20 MB。

最终交付：

- `build/release/YuanC-Client-<Version>.exe`
- `build/release/YuanC-Client-<Version>.exe.sha256`

校验文件为小写 SHA256、两个空格、exe 文件名和换行。维护人员可用 `Get-FileHash <exe路径> -Algorithm SHA256` 对比。调试符号保留在发布目录，不必交客户；不要把服务器配置或配对凭据塞进发布包。

用于自动更新时，出包后再执行 `python scripts/release/sign-winclient.py --exe build/release/YuanC-Client-<Version>.exe --key C:/Users/Administrator/.secrets/yuanc-winclient-signing.pem`，生成同版本 manifest.json 和 manifest.json.sig。私钥只能位于仓库外。把三件套经 scp 送到节点后用 `exitnode winclient publish` 发布；签名后的清单字节不可修改。具体步骤及真机待验证项见 [自动更新说明](自动更新说明.md)。本单不修改默认版本号，不执行正式发版。

## 构建期的第三方组件

唯一来源清单是 `winclient/third_party/manifest.json`。构建前自动执行 `scripts/release/fetch-third-party.ps1`：

1. 压缩包已在 `winclient/third_party/cache/` 且哈希正确时完全不联网；只有不存在时才下载清单中的 URL。
2. 缓存包或下载包哈希不符立即失败，不换源、不更新清单。损坏缓存必须由维护人员查明原因，再显式移走后重新取得官方原包。
3. 解出清单指定成员并核对文件哈希。`winclient/third_party/bin/` 中的目标文件已正确时不重写；不正确时重新提取，提取结果不符则失败。
4. 生成固定字段顺序的 `kernel-manifest.json`，包含 sing-box 内核版本与两文件哈希、资源逻辑名。没有时间戳或机器路径；内容相同不重写。
5. 三个固定嵌入资源名为 `YuanC.Kernel.sing-box.exe`、`YuanC.Kernel.wintun.dll`、`YuanC.Kernel.manifest.json`。

缓存与解出文件均不入库；只提交来源清单和生成逻辑。离线施工使用派单方提供的官方原包；有外网且无缓存的构建环境会走同一清单的下载与校验。

1.13.21 压缩包另含 libcronet.dll，本产品不使用，不加入组件清单。
派单方实测仅提取 sing-box.exe 即可正常执行版本查询与配置检查。

### 升级第三方件

先记录升级理由、上游变更和兼容性影响。人工从官方发布地址取得目标版本，列出压缩包目录确认 amd64 成员，计算压缩包及解出文件的 SHA256，再修改清单中的版本、URL、成员路径和两个哈希。禁止让脚本自动追最新版本或在失败时替换来源、哈希。

重新构建并通过全部自动检查后，先在干净的 Win10/Win11 虚拟机验证启动、解包、权限、连接、断开与安全软件提示，再允许交付客户。保持旧包用于回退。运行目录以 sing-box 内核版本区分；若只升级 wintun，同一版本目录内哈希不同的 dll 会被新包替换。回退旧包时同样按旧清单修复。

## 客户电脑首次运行

默认内核落在 `%ProgramData%\YuanC\bin\<内核版本>\`，sing-box.exe 与 wintun.dll 位于同一目录。客户先双击程序，再点击「安装后台服务(需管理员确认一次)」并确认一次 UAC。安装后服务自动启动，登录后界面只显示托盘；关闭窗口隐藏到托盘，退出界面不影响隧道。程序安装到 `%ProgramFiles%\YuanC\app\<Version>\YuanC-Client.exe`。后台服务保留原防火墙恢复流程，再安装内嵌组件；以后正常打开界面不要求管理员。配置 `server.json` 未提供 `sing_box_path` 时使用内嵌内核；已有路径须位于 `%ProgramFiles%\YuanC` 之下才使用。

分发版的 `server.json` 必须同时写 `server_url` 与 `server_spki_sha256`（算法见 [docs/authserver/接口说明.md「对外表现与证书指纹」](../authserver/接口说明.md#对外表现与证书指纹)），缺了指纹客户端会提示「缺少有效的证书指纹」。占位示例（部署时替换地址、端口和指纹）：

```json
{"server_url": "https://<鉴权服务器IPv4>:<端口>", "server_spki_sha256": "<44 个字符的证书公钥指纹>"}
```

每次后台服务启动校验磁盘文件，正确文件不重写；缺失或被篡改的文件从嵌入资源写入同目录临时文件后覆盖移动，随后读回校验。校验失败会删除错误文件并停止初始化，界面显示“连接内核文件校验失败,请重新安装客户端”，不会继续启动内核。临时文件在操作结束时清理。

Core 只接收清单和资源流工厂，App 提供程序集资源；自动测试使用临时目录和假源，不会写客户电脑的 ProgramData 或修改防火墙。

## 给客户的未签名提示文案

> 首次打开时，Windows 可能提示“Windows 已保护你的电脑”或“未知发布者”，这是当前版本尚未进行发布者签名的提示。请先确认程序来自我们提供的交付渠道，并请维护人员核对校验值。确认无误后，选择“更多信息”，再选择“仍要运行”。点击安装后台服务后系统询问管理员权限时，请确认打开的是本客户端。若没有“仍要运行”选项，或安全软件报告威胁，请停止操作并联系维护人员；不要关闭安全软件或绕过单位管理策略。

本任务未在干净虚拟机或真实客户电脑运行，尚未验证 SmartScreen、Defender、UAC、真实网卡与隧道行为。编译、单测和单文件大小/哈希检查通过不能替代这些真机项。

后台服务、卸载及真机待验证清单见 [服务化与自启说明](服务化与自启说明.md)。发布包应包含 Windows Forms 托盘和服务管理组件；缓存包为 System.ServiceProcess.ServiceController 10.0.9，允许其 System.Diagnostics.EventLog 10.0.9 间接依赖，但不直接引用或使用事件日志。
