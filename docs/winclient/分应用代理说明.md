# Windows 客户端分应用代理

## 两种代理范围

默认仍为「全部流量」。客户明确选择「仅指定程序」时，只把名单中的程序送到澳洲出口，**其他程序直连、不受本模式的断网保护**。这与「自用模式 / 邀请码模式」是两个独立设置；两种会话来源都可选择代理范围。

| 项目 | 全部流量（默认、推荐） | 仅指定程序 |
|---|---|---|
| 接管范围 | 既有 TUN 全局接管，默认出站 proxy | TUN 仍接管路由，匹配名单的程序走 proxy，其他程序走 sing-box 的 direct 出站 |
| DNS | 全机 DNS 经隧道 DoH | 同左，DNS 配置整段不改，不按程序分流 |
| IPv6 | 既有全局 IPv6 阻断 | 指定程序与后台服务的 IPv6 路由阻断；其他程序不加本项目 IPv6 限制；全机 DNS 仍只解析 IPv4 |
| 断网保护 | 三档开启、默认出站 Block，临时停用可管理的第三方允许规则；既有例外不变 | 三档开启，默认出站动作保持原值，不停用任何第三方规则；仅按名单程序阻断非 TUN 源地址出站 |
| 自检第七项 | 默认 proxy、IPv6 block、DNS detour proxy、无 direct 出站 | 默认 direct、指定程序 proxy、指定程序 IPv6 block、DNS detour proxy |
| 自检第八项 | 后台服务探测固定 IPv6 地址 | 跳过整机 IPv6 探测，计入「未能检查」 |
| 适用场景 | 希望所有软件统一使用澳洲出口，断网保护范围更广 | 只让明确列出的软件走澳洲出口，并接受其他软件从本地联网 |

上述是配置与保护机制的范围，不是已经通过真机零泄漏验收的声明。仅指定程序模式有下文列出的进程识别和子进程局限。销售口径只承诺指定程序的配置与保护范围，不能承诺全机、同一账号所有进程或任何检测都查不出。

## 设置与恢复记录

先点击断开，再选择范围、添加程序或移除所选。名单最多 32 个程序；仅指定程序模式没有任何程序时拒绝连接。连接、重连、保护保持或尚未回到已断开状态时不能改范围。断网保护恢复记录尚在时，也不能改范围；应先按原范围连接并正常断开，不能删除恢复记录来绕过检查。

服务保存 `%ProgramData%\YuanC\run\routing.json`，示例：

```json
{"mode":"apps","apps":["C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe"]}
```

`mode` 只接受 `global` / `apps`，不分大小写；写盘使用小写。路径逐项去掉首尾空白，必须是以 `.exe` 结尾的完整路径，最长 260 字符，不含控制字符或 `..` 段，按不分大小写去重。切回 `global` 仍保留名单，方便以后切回来。文件缺失、损坏或校验失败时回到全部流量和空名单。保存先写 `.tmp`、刷盘，再原子替换；临时文件会清理。

新建的仅指定程序保护记录在 `killswitch-state.json` 中包含 `mode="apps"`。旧格式没有 mode 时按 `global` 处理；连接前对照当前范围，模式不一致则拒绝进入连接流程。后台服务重启后的保持保护路径也经过此检查。主动断开沿用原恢复流程，删除本项目前缀规则，按首次记录恢复三档 Enabled 与默认出站原值。全部流量模式的配置渲染、脚本和状态文件格式保持原样。

## 程序匹配与后台服务

名单按照**可执行文件完整路径、不分大小写**匹配。sing-box 使用 `process_path_regex`，防火墙使用 `-Program`，双方使用同一份路径。路径转成 `(?i)^…$`，只转义 RE2 元字符，空格不转义；不按文件名或窗口标题匹配。

例如 Chrome 常见真实路径是 `C:\Program Files\Google\Chrome\Application\chrome.exe`，也可能在 `Program Files (x86)` 或用户目录。必须选择实际安装位置，不能照抄示例。Discord 等软件把版本号放在目录名中，升级后完整路径改变，**隧道匹配和防火墙保护会同时失效，须重新添加**；界面也显示此提示。

后台服务当前可执行文件自动并入隧道路由名单，用于出口核验；**服务进程不自动加入防火墙阻断名单**。分发版到鉴权服务器的连接按服务进程路径、鉴权 IPv4 `/32` 和鉴权端口匹配，单独使用 direct 出站，以保证鉴权与续期可直连；自用版没有这条鉴权规则。

路由规则顺序为：原有 DNS 规则（原顺序）→分发版服务鉴权直连→名单加服务进程的 IPv6 阻断→名单加服务进程走 proxy；默认 direct。原来的全局 IPv6 阻断从仅指定程序配置中移除。route 的其他设置及 inbounds 不改，网卡名称、auto_route、strict_route 仍由既有传输层补齐。缺少 route、dns、outbounds 或找不到 detour 为 proxy 的 DNS 服务器时，拒绝启用本模式。

出口核验显示「已核验(后台服务出口)」或「不一致(后台服务出口)」。它只证明后台服务这一个进程的本次出口，不能证明每个指定程序或它的子进程都走隧道。重连期间服务可能直连，因此不发出口探测，按既有周期重排；核验和巡检仍只报告，不自动断开、不撤保护。

## 逐程序断网保护

连接时先保存三档配置的 Name、DefaultOutboundAction、Enabled 原值与模式，再开启 Domain / Private / Public。每个名单程序按输入顺序创建 `YuanC-KS-App-1` 至 `YuanC-KS-App-n`，方向 Outbound、动作 Block、Profile Any、Program 为该完整路径，LocalAddress 为下面五段：

```text
0.0.0.0-126.255.255.255
128.0.0.0-172.19.0.0
172.19.0.2-255.255.255.255
::2-fdfe:dcba:9876::0
fdfe:dcba:9876::2-ffff:ffff:ffff:ffff:ffff:ffff:ffff:ffff
```

这覆盖除回环与 TUN 自身源地址 `172.19.0.1` / `fdfe:dcba:9876::1` 之外的本地源地址，包含 `0.0.0.0/8`。它与全局模式按源地址放行 TUN 的思路对应：允许指定程序通过 TUN 交给内核处理，阻止其用物理网卡源地址直接出站。内核退出后，指定程序不能因路由恢复而直接改走物理网卡。IPv6 同时由指定程序路由规则阻断。

本模式不改默认出站动作，不创建 Allow 规则，也不修改其他程序的规则。三档开启会使电脑原有规则重新生效；如果电脑原默认出站本来就是 Block 或原有其他阻断规则，仍受这些原规则限制，本功能不会替用户放宽。

套用后必须确认 MpsSvc 正在运行，并在 **ActiveStore** 核对恰好三档全部 Enabled=True、每条预期程序规则存在且 Enabled=True、Action=Block。失败保留恢复记录、拒绝启动连接。巡检只重新开启关闭的配置档，不动默认动作；在 ActiveStore 检查程序阻断规则，缺失、禁用或动作不是 Block 都触发重建，`newly_disabled` 始终为空数组。服务或配置档仍无效时告警，规则重建失败同样告警。

## 已知局限与使用建议

1. **无法识别的流可能直连。** sing-box 在 Windows 按连接源端口反查进程；UDP、QUIC 或高并发下可能发生识别竞态。认不出进程的流落到 direct，并由 sing-box 自己直连发出，指定程序的防火墙规则拦不到。WebRTC 公网候选可能因此变成本地公网 IP。建议名单内浏览器配合关闭 QUIC，或把 WebRTC 设为仅代理 UDP；这些浏览器加固属另卡，本单不自动实施，不承诺已经解决。
2. **DNS 与网卡限制仍作用于全机。** Windows 的域名解析通常由 svchost.exe 中的 Dnscache 代发，按指定程序分 DNS 匹配不到，可能导致泄漏。因此全机 DNS 保持经隧道 DoH，直连软件也拿到澳洲侧解析结果，国内 CDN 可能选择境外节点而变慢；`strategy=ipv4_only` 对全机生效。Windows 的 strict_route 会封掉非 TUN 网卡的 53 端口，自己绑定物理网卡解析的程序可能 DNS 失败。不要把「其他程序直连」理解成其 DNS 完全不受影响。
3. **环境一致性仍是整机设置。** 时区与机器级 Chrome / Edge 策略没有按名单隔离。名单外直连浏览器也可能报告澳洲时区和 en-AU，银行、支付网站可能判为异常。该模式没有缩小环境设置的范围。
4. **异名子进程和名单外软件不继承规则。** 同平台桌面客户端、另一个浏览器、WebView2、更新程序以及选中软件自己拉起的异名联网子进程，既不因父进程入选而走隧道，也不受父进程断网保护。从本地 IP 登录同一账号可能出现同账号两地并发。建议按实际使用情况把下表所需进程一并加入，每个都选择其真实完整路径。
5. **选错外壳会整体直连。** 指纹浏览器的启动外壳可能不是联网内核；Edge 与 WebView2 也是不同程序。应核对实际联网可执行文件，不能只选择桌面快捷方式或启动器。常见文件名见下表；文件名仅作查找线索，不能代替完整路径。
6. **出口核验覆盖有限。** 后台服务核验一致不能发现名单外软件、漏选子进程或进程识别竞态，更不能证明全机出口或零泄漏；必须逐个软件在真机核验。
7. **其他本机代理会改变实际出网进程。** 指定程序若按系统代理连接到 `127.0.0.1` 上的其他代理工具，实际联网的可能是名单外代理进程，从而直连。使用前关闭其他代理工具及相关系统代理设置，不把回环连接视为已通过本隧道。
8. **组策略可能使阻断无效。** 三档配置被组织策略关闭，或「本地规则合并」被关闭时，本地创建成功不代表 ActiveStore 生效。套用会拒连，巡检会告警；应由管理员处理，不能关掉核验或改用静默直连。

| 软件或作用 | 需要核对的真实可执行文件 / 建议一并加入 |
|---|---|
| Google Chrome | `chrome.exe`；如会联网更新，再检查 `GoogleUpdate.exe` 的实际路径 |
| Microsoft Edge | `msedge.exe`；WebView2 应用还需 `msedgewebview2.exe`；更新进程核对 `MicrosoftEdgeUpdate.exe` |
| Firefox | `firefox.exe`；环境一致性不覆盖其浏览器策略 |
| 指纹浏览器 | 选择实际浏览器内核的 `.exe`，同时核对需要联网的启动外壳；名称与路径以该产品实际进程为准 |
| Steam | `steam.exe` 及联网子进程 `steamwebhelper.exe` |
| 微信类桌面应用 | 主程序及联网子进程 `WeChatAppEx.exe`，按实际版本核对 |
| Discord / 其他 Electron 应用 | 主程序和需要联网的 `Update.exe`；版本目录改变后重新添加 |
| 内嵌网页应用、同平台桌面客户端、第二浏览器 | 应用主进程与其实际使用的 `msedgewebview2.exe` 或其他异名联网内核，不能只添加常用浏览器 |

## 自检与自动验证范围

第七项名称仍为「配置无直连路径」，仅指定程序模式的 Detail 以「仅指定程序模式:」开头，检查指定程序的 proxy / IPv6 block 规则覆盖完整名单以及 DNS detour；不是说其他程序没有直连。第八项返回「跳过」，明细为「仅指定程序模式不检测整机 IPv6;指定程序的 IPv6 已由配置与防火墙阻断」。其余六项判定不变；其余项目全部通过时汇总为「7 项通过,1 项未能检查」。

自动测试覆盖设置校验、原子保存、配置规则顺序、全局原文返回、DNS 原文保留、脚本文本、恢复模式检查、连接与巡检替身、协议往返及拒绝不可信调用者。只生成和检查脚本文本，不执行主机防火墙或环境脚本。sing-box 1.10.7 字段兼容性已由派单方使用本工位同版缓存经调度验证：合法配置退出 0，把字段改为 `process_path_regexx` 后报未知字段、退出 1。施工方按答复采用该证据，未重复解包或执行。

## 真机待验证清单

以下全部待验证，自动测试不能代替。应在隔离 Windows 10 / Windows 11 机器记录连接前后的规则、配置档、程序路径、出口和抓包结果：

- 仅指定 Chrome：Chrome 出口为澳洲，另一个名单外程序的业务连接出口为本地。
- 结束 sing-box 进程后：Chrome 无法联网，名单外程序业务连接照常；另行记录全机 DNS 经隧道造成的解析影响。
- 三档防火墙原来全关：套用后全部开启，ActiveStore 程序规则为启用的 Block；主动断开后三档恢复原来的关闭值，默认出站动作全过程未被本模式更改。
- Chrome 打开 DNS 泄漏测试页：解析器显示为经隧道的 Cloudflare / 澳洲侧，而非国内运营商；物理网卡抓包无 53 端口明文查询。
- Chrome WebRTC 公网候选为澳洲 IP；分别记录 UDP / QUIC 与高并发时的结果，失败不得抹去或标为通过。
- IPv6 网站在指定 Chrome 中打不开；名单外程序不被本项目按程序阻断。
- 完整路径含空格、括号、加号，及大小写不同的同一路径，均能命中路由与防火墙；升级换目录后旧路径失效、重新添加恢复。
- WebView2 类应用将主程序与内核两个进程都加入后，两者业务出口均为澳洲；再核对异名子进程清单。
- 分发版仅指定程序模式下续期成功，鉴权连接到指定 IP 与端口且不经隧道；自用版不出现鉴权例外。
- `New-NetFirewallRule` 实际接受上面五个 LocalAddress 地址段；逐条核对本地源地址过滤条件。
- 模拟策略关闭配置档或禁止本地规则合并：连接拒绝，运行期巡检告警；没有静默撤保护或自动断开。
- 连接中改范围被拒；遗留恢复记录模式不一致时拒连；正常断开后才可改范围与名单；界面拒绝操作后回读实际值。
- 切回全部流量后，配置、保护、巡检与改前一致；不遗留 App 规则，旧全局恢复流程照常。

范围说明及其他恢复机制见 [断网保护加固说明](断网保护加固说明.md)、[环境一致性说明](环境一致性说明.md) 与 [服务化与自启说明](服务化与自启说明.md)。
