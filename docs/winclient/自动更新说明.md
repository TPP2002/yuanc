# Windows 客户端自动更新（自用模式）

后台服务在启动五分钟后首次检查，之后每六小时检查；只有连接状态为已连接时才请求更新。窗口的“检查更新”通过 `check_update` 发起检查，立即显示当前进度，同一时刻只进行一次更新。界面不直接安装程序，也不操作服务或注册表。

## 更新来源和信任

固定更新源是 `http://198.18.255.1/winclient/`。客户端原有全局代理规则将它送入加密隧道，节点第一条路由把 `198.18.255.1/32` 交给 `admin-local`，改送配置中的本机托管端口（示例 `127.0.0.1:8443`）。不开放公网端口，不使用域名、独立服务器、代理设置或 HTTP 重定向。节点须使用回环监听配置；不要改为公网监听。

`latest.json` 只是未签名索引，其版本、文件名、大小、哈希必须与已验签清单一致。客户端仅信任 `TrustedPublisher` 内置的 SubjectPublicKeyInfo 公钥，使用框架 ECDSA P-256、SHA-256 和 DER 签名格式验证清单原始字节。清单中的产品、版本、文件名、哈希、大小、构建时间、最低后台版本均严格校验，未知扩展字段忽略。签名失败、大小或哈希不符、版本不高于当前、带坏版本标记的包均不安装。

索引与清单各限 64 KiB，签名限 4 KiB，程序限 1 GiB（防呆线，安装包大小不设硬上限，负责人 2026-11-27 定）。连接超时十五秒，程序下载整体超时二十分钟。已有 `.part` 文件带 `Range: bytes=N-` 续传；完整响应会重新下载，部分响应必须符合期望范围。下载后始终重新核对整个程序的大小与哈希。

## 磁盘布局

- `%ProgramData%/YuanC/updates/incoming/`：下载中的 `<版本>.exe.part` 和已验过的 `<版本>.exe`。
- `updates/pending.json`：切换前写入 `old_exe`、`old_version`、`new_exe`、`new_version`、`started_at`。
- `updates/history.jsonl`：每行包含版本、状态、时间及可选中文原因；状态有 staged、ok、rolled_back、failed、skipped，回退自身失败另记 needs_manual。
- `updates/<版本>.bad`：进程级健康失败标记，后续检查跳过该版本。
- `%ProgramFiles%/YuanC/app/<版本>/YuanC-Client.exe`：独立版本目录。先写临时文件、刷盘、Move，再读回校验。原程序目录始终保留到新版健康检查完成。
- `%ProgramData%/YuanC/run/update.log`：更新助手脱敏日志；不记录异常原文、私钥、路径或哈希原文。

记录采用 `.tmp` 写入后原子覆盖。服务启动时为 updates 根目录应用仅 SYSTEM 与管理员可写的权限；真实权限隔离仍需真机验证。坏记录不被当成成功，未完成记录存在时协调器不会另起更新覆盖它。

## 更新助手与回退

服务完成校验与暂存后，先落 pending，再用当前运行中的旧程序启动 `--apply-update`。不等待助手退出。助手及系统命令均使用绝对路径、参数列表、隐藏窗口；系统服务工具来自系统目录。

1. 停止 YuanCService，并在三十秒内确认停止。
2. 复用原安装参数，将服务指向新版程序的 `--service` 角色，启动并在三十秒内确认运行。
3. 最多六十秒检查 `YuanC-Control` 管道（每次连上先核验服务端身份，核验不过与连不上同样处理），要求 status 成功且 `service_version` 等于新版；期望连接记录为 true 时，再最多等一百二十秒进入 Connected。六十秒内管道始终不通时，先查服务进程：服务处于运行状态且服务进程的程序完整路径（规范化后不分大小写比较）等于新版程序，说明新版确实在跑、只是管道不通（例如被别的程序占满），按非进程级失败处理；查不到或不是新版程序，按进程级失败处理。
4. 成功后把 HKLM Run 的 YuanC 值改为新版 `--tray`，写 ok，删 pending，再清理 app 下多余的合法版本目录。保留新版、切换前版本及仍被 pending 引用的目录；不遍历符号链接，不删非法目录名或 app 外目录。仍被旧界面占用的目录保留。
5. 失败时停止新版、重新配置旧版、启动并确认运行。管道从未正常响应且服务进程不是新版程序，或一百二十秒等待中版本不符，属于进程级失败，写 `.bad`；管道不通但服务进程确实是新版程序、或仅连接超时，不写 `.bad`，只记「更新未完成，已恢复旧版，下次再试。」，允许下次再试。两者都记录 rolled_back。回退自身失败保留 pending，记录 needs_manual，提示维护人员处理。

服务启动顺序为更新恢复、运行时创建、协调器与管道启动。管道无需等待网络连接完成即可提供状态，防止网络慢被误认为新版程序损坏。pending 超过十分钟时，当前是新版则补成功收尾，当前是旧版则标坏并记回退；不足十分钟保持原记录，避免与助手竞争。

协议快照在连接状态之外增加 `service_version` 与 `update`（stage、version、message、checked_at）。ClientSnapshot 本身不变；更新变化也触发 subscribe 推送。旧界面发现后台版本不同后提示“后台已更新到……，下次打开界面将使用新版”，不自动重启界面，托盘菜单不变。

## 维护人员发版

1. build：按打包说明生成带版本号的单文件程序，本单默认版本仍为 0.1.0，不发布新版本。
2. sign：`python scripts/release/sign-winclient.py --exe build/release/YuanC-Client-<版本>.exe --key C:/Users/Administrator/.secrets/yuanc-winclient-signing.pem`。私钥保持仓库外；不要重新排版签名后的清单。
3. scp：经现有管理通道将程序、清单、签名三件复制到节点临时目录，不传私钥。
4. publish：`exitnode winclient publish --exe <程序> --manifest <清单> --signature <签名>`，然后 `exitnode winclient status` 核对版本、大小、时间。

## 真机待验证清单

以下均未执行，不以单测或构建通过替代：

- Windows 10/11 LocalSystem 实际切换服务路径、自启注册表、旧程序启动助手且无窗口。
- 新版正常、管道不响应、版本不符、网络连接超时，以及回退启动失败的完整路径。
- 新版在跑但管道被占满时的回退不标坏：切换期间用别的程序占满管道，确认六十秒后回滚旧版、history 记「下次再试」、不生成 `.bad`；服务进程查询（服务控制管理器取进程号、按进程号取程序路径）在 LocalSystem 助手下真实可用。
- 切换前后断电或强制终止助手，验证十分钟恢复边界、pending 保留、坏版本跳过。
- 真实隧道内下载、断点续传、服务端返回完整文件后的重新下载、断线取消与空间不足。
- updates 权限、目录链接拒绝、旧界面占用目录保留和至少一个可运行旧版本保留。
- Debian 上 admin 单元启动、旧占位参数兼容、SIGTERM 退出、回环监听、隧道可达而公网不可达。
- 界面在后台更新后重连、版本提示、下次打开走新版；不自动重启旧窗口。
