# Windows 客户端诊断导出说明

这份说明写清怎么导出诊断、导出文件里每一段装什么、五份日志各记什么、脱敏规则、大小上限与超限裁剪次序。导出文件只用于排查问题，不含出口 IP、节点地址、令牌、配对内容或用户目录名。

## 怎么导出

- 在「更新与诊断」页点「导出诊断…」。默认写到当前用户桌面，文件名形如 `澳洲出口客户端-诊断-20261128-193000.json`（`澳洲出口客户端-诊断-<年月日-时分秒>.json`），也可以在选择框里换位置。
- 界面先向后台服务发只读指令 `read_diagnostics`，最多等 45 秒；后台服务不认识这条指令时退回 `read_audit` 与 `read_selfcheck`，至少把防火墙审计与环境自检带上。
- 任何情况下都会写出文件：后台服务没连上、指令不支持、采集出错都一样，文件里用 `service_error` 说明原因。

## 文件顶层结构

顶层键依次是：

| 键 | 装什么 |
|---|---|
| `schema` | 固定为 `1`。 |
| `exported_at` | 界面写文件时的本地时间（ISO 8601）。 |
| `ui` | 界面这边看到的快照：`version`、`service_version`、`service_availability`、`state`、`status`、`message`、`protection_active`、`mode`、`exit_status`、`guard_status`、`environment_enabled`、`environment_status`、`self_check_status`、`routing_mode`、`routing_apps`（只留文件名）、`update_stage`、`update_message`。 |
| `service` | 后台服务采集到的诊断对象；没取到时为 null。 |
| `service_error` | 没取到后台诊断时的原因原文，例如「后台服务没有连上。」。 |
| `firewall_audit` | 后台不认识 `read_diagnostics` 时退回读到的防火墙审计；正常导出时为 null（审计在 `service.firewall_audit` 里）。 |
| `self_check` | 同上，退回读到的环境自检报告。 |

## service 段逐键说明

`service` 由后台服务的 `DiagnosticsCollector` 生成，键依次是：

| 键 | 装什么 |
|---|---|
| `schema` | 固定为 `1`。 |
| `collected_at` | 后台采集时刻（UTC，ISO 8601）。 |
| `version` | 后台服务版本。 |
| `test_build` | 是否测试包。 |
| `system` | `os`、`arch`、`culture`、`time_zone`、`utc_offset_minutes`、`uptime_minutes`。 |
| `snapshot` | 后台看到的连接快照（状态、提示、保护、模式、出口状态、网卡巡检、环境、自检、代理范围与名单文件名），不含出口 IP。 |
| `desired` | `run/desired.json` 里「开机要不要接着连」的布尔值，读不到为 null。 |
| `killswitch` | `state`（`exists`、`bytes`、`modified_at`、`summary`）、`audit_file`（`exists`、`bytes`、`modified_at`）、`wfp_off`、`route_off`。 |
| `wfp_filters` | 过滤层过滤器：`count` 与 `names`（已脱敏）；过滤层不可用时为 null。 |
| `adapters` | 网卡清单：`name`、`description`、`ipv4`、`ipv6`（地址带前缀长度，公网地址已遮）。 |
| `firewall` | 系统防火墙现状对象：`service`、`profiles_local`、`profiles_effective`、`own_rules`、`outbound_rules_total`、`outbound_rules_enabled`、`outbound_allow_enabled`。 |
| `firewall_error` | 防火墙现状没读到时的一段提示原文。 |
| `network` | 路由与 DNS 现状对象，见下节；没读到为 null。 |
| `network_error` | 路由与 DNS 现状没读到时的一段提示原文。 |
| `channels` | 连接内核的通道状态对象，只有测试包有，见后文；没读到时为 null。 |
| `channels_error` | 通道状态没读到时的一段提示原文，只有测试包有。 |
| `node_reach` | 从物理网卡直连节点主通道端口的握手探测结果，只有测试包有，见后文。 |
| `node_reach_error` | 主通道握手探测没做或失败时的一段提示原文，只有测试包有。 |
| `ipv6_reach` | 按系统默认路由连 IPv6 探测点的握手探测结果，只有测试包有，见后文。 |
| `ipv6_reach_error` | IPv6 握手探测没做或失败时的一段提示原文，只有测试包有。 |
| `logs` | 五份日志的末尾，见后文。 |
| `firewall_audit` | `run/firewall-audit.json` 的内容（解析后脱敏）。 |
| `self_check` | `run/selfcheck.json` 的内容（解析后脱敏）。 |
| `omitted` | 因文件过大被裁掉的段名。 |
| `errors` | 各段采集失败时的异常类型名或固定原因，例如 `firewall`、`network`、`killswitch_state_file`、`firewall_audit_file`。 |

后台服务真实导出时 `network` 与 `network_error` 两个键总在（`ClientRuntime` 总会接上路由与 DNS 探测）；只有构造采集来源时没接这条探测（只在单元测试里出现）才不带这两个键。取到结果且能解析时 `network` 是处理后的对象、`network_error` 为 null；结果带错误时 `network` 为 null、`network_error` 是那段文字；JSON 解析不了时 `network` 为 null，异常原因记进 `errors.network`；来源抛异常（取消除外）时两个键都是 null，异常类型名记进 `errors.network`。

`channels`、`channels_error`、`node_reach`、`node_reach_error`、`ipv6_reach`、`ipv6_reach_error` 六个键只有测试包接了对应探测才出现，而且成对出现：正式包或没接来源时整对都不出现（后者只在单元测试里出现），所以根键清单与次序和改动前一致。这六个键不参加超限裁剪。

### killswitch.state.summary 里的 profiles

状态文件是断网保护套用前保存的恢复记录。摘要保留原有口径：标量按原值（字符串过脱敏），数组给 `<键名>_count`，对象给 `<键名>_keys`；顶层名为 `profiles` 的数组是例外：除了原有的 `profiles_count`，另给一个 `profiles` 数组，每项只带 `Name`、`DefaultOutboundAction`、`Enabled` 三个属性（原对象里有哪个带哪个），字符串值过脱敏，不是对象的元素跳过。这样导出里能直接看到套用断网保护之前保存的三档防火墙默认出站。

### network 段

`network` 是把探测脚本最后一行 JSON 解析后、把所有字符串值脱敏得到的对象，键有：

- `routes_active`、`routes_persistent`：活动存储与持久存储里的路由，每条含 `prefix`（目标前缀）、`next_hop`（下一跳）、`alias`（网卡名）、`index`（接口序号）、`metric`（路由跃点）、`loopback`（是否走回环接口）。脚本只取前缀长度 /0、/1、/2 的路由。
- `interfaces`：`alias`、`index`、`family`、`metric`、`state`（连接状态）、`dhcp`。
- `dns`：`alias`、`family`、`servers`（该网卡配置的 DNS 服务器地址数组）。
- `kernel_processes`：连接内核进程，`id`、`started`、`path`。
- `security_products`：系统安全中心登记的杀毒软件与防火墙产品，每项含 `kind`（登记类别）、`name`（名称）、`state`（产品状态码）。

怎么认三条关键证据：

- **默认路由**：`prefix` 为 `0.0.0.0/0`、`loopback` 为假的那条，就是整机出网走的物理默认路由；`dns` 里对应网卡的 `servers` 就是系统当前指向的 DNS。
- **本产品的回环兜底路由**：两条，`prefix` 为 `0.0.0.0/1` 与 `128.0.0.0/1`，`loopback` 为真，`metric` 为 `9473`；活动与持久两处存储都应在。
- **隧道路由**：`prefix` 为 /2 的四条 IPv4（`0.0.0.0/2`、`64.0.0.0/2`、`128.0.0.0/2`、`192.0.0.0/2`）走隧道网卡；`dns` 若指向隧道地址，说明解析经隧道。

路由前缀只有 /0、/1、/2 三种长度，不指向具体主机，所以 `prefix` 的值原样保留，不做脱敏；其余字符串值按脱敏规则处理。`network` 段不参加超限裁剪。

### channels、node_reach、ipv6_reach 三段（只有测试包有）

这三段只有测试包（`-TestBuild`）接了探测才出现，正式包导出里没有。

`channels` 是连接内核状态口的读取结果：

- `selected`：内核当前选中的通道名（`main` 主通道或 `backup` 备用通道），读不到为 null。
- `main`、`backup`：主通道与备用通道各一个对象，键依次是 `last_delay_ms`、`last_test_at`、`test_ok`、`test_delay_ms`、`test_status`。`last_delay_ms` 与 `last_test_at` 是内核最近一次测速成功时的延迟（毫秒）与时间；`test_ok`、`test_delay_ms`、`test_status` 是导出那一刻现场复测的结果，`test_delay_ms` 为 null 表示这次没测到延迟，`test_status` 是状态口的应答码或 0（请求异常）。

`node_reach` 与 `ipv6_reach` 都是从本机直接做一次 TCP 连接与一次标准 TLS 握手（不传应用数据）的结果：

- `bound`：TCP 连接是否绑到了物理默认出口（只有 IPv4 目标且取到物理默认出口时才为真）。
- `tcp`、`tcp_ms`：TCP 连接结果与用时毫秒。`tcp` 取值：`ok`（连上）、`refused`（对端拒绝）、`reset`（连接被重置）、`unreachable`（网络或主机不可达）、`timeout`（本步超时）、`failed`（其余失败）。
- `tls`、`tls_ms`：TLS 握手结果与用时毫秒。`tls` 取值：`ok`（握手完成）、`timeout`（本步超时）、`reset`（握手中途被重置）、`closed`（对端直接关闭连接）、`failed`（其余失败）；`tcp` 不是 `ok` 时 `tls` 与 `tls_ms` 都是 null。
- `tls_protocol`：握手完成时的协议版本文字。
- `cert_errors`：证书校验发现的问题文字，例如 `None`、`RemoteCertificateChainErrors`。
- `cert_issuer`：证书签发方，超过 200 字截断。

怎么读：

- `selected` 是内核当前选中的通道；某条通道 `test_ok` 为假，说明导出那一刻它测不通。
- `node_reach` 是从物理网卡直连节点主通道端口：`tcp_ms` 只有几毫秒到十几毫秒而节点在海外，说明连接被本机或本地网络里的设备先接走了；`tcp` 为 `ok` 而 `tls` 是 `reset` 或 `closed`，说明握手中途被关掉；`tls` 为 `ok` 且 `cert_issuer` 是正规签发机构，说明这条路对标准握手是通的；`cert_issuer` 是安全软件或网关的名字，说明中间有设备在拆看加密连接。
- `ipv6_reach` 是按系统默认路由连 IPv6 探测点（与环境自检「IPv6 已封堵」那一项连的是同一个地址）：`tcp` 为 `ok` 而 `tls` 不是 `ok`，说明 IPv6 连接被隧道接走后拒绝，并没有真的通出去；`tls` 为 `ok`，说明 IPv6 真的能直连。

这三段都不含目标地址、端口、主机名与证书主题；后台服务这次启动以来没连接过时 `node_reach` 为 null、`node_reach_error` 写明原因。

## 五份日志各记什么

`service.log`：后台服务运行记录，含服务启动、数据目录权限异常、管道拒绝与运行时创建阶段的提示。

`connect.log`：连接记录，含连接请求、取会话、每个动作起止与用时、状态迁移、失败处理与放弃并恢复，以及每次防火墙脚本的阶段、退出码、用时与错误摘要（`防火墙脚本[<阶段>] …`）和过滤层安装与移除的结果。行格式见[连接记录说明](连接记录说明.md)。

`sing-box.log`：连接内核的标准输出与标准错误，脱敏后写入。测试包会把内核日志开到 `warn` 级，正式包不开。这份日志里的主机名会被换成 `[域名]`；导出时去掉颜色码。

`update.log`：自动更新的检查、下载、安装与回退记录。

`killswitch-recovery.log`：防火墙恢复脚本非零退出或超时时追加的行，记 UTC 时间、`restore` 或 `fallback` 阶段与退出码（超时时阶段后面写 `timeout`）。

`logs` 段每份日志是一个对象：`missing`、`bytes`、`truncated`、`error`、`lines`。`lines` 是最后若干行，行数预算依次收紧为 400、200、100、40、10、0；单行超过 2000 字截断并加「…」。

## 脱敏规则

- 公网地址换成 `[公网地址]`；IPv6 公网地址同样处理。
- `C:\Users\<用户名>` 里的用户名换成 `[用户]`。
- 带 `token=`、`password=` 这类标签的值与已登记的凭据值换成 `[已隐藏]`。
- `sing-box.log` 里的主机名换成 `[域名]`。
- 内网地址（例如 `192.168.1.52`、`10.0.19045`）原样保留，方便判断局域网与网段。
- 文件不含出口 IP，也不写节点公网地址与端口之外的连接参数。

## 大小上限与超限裁剪次序

- 管道单条消息上限 1 MiB；采集目标是不超过 900 KiB，留出管道与 JSON 包装的余量。
- 超限时先逐档收紧日志行数预算：400 → 200 → 100 → 40 → 10 → 0；仍超限就依次丢掉 `firewall_audit`、`self_check`、`adapters`，丢掉的段名写进 `omitted`。
- `network` 与 `wfp_filters` 不参加裁剪；单条诊断比管道上限还大时，后台服务回「诊断内容过大，请联系管理员。」，界面把这个原因写进 `service_error` 并仍写出文件。

## 谁能调 read_diagnostics

`read_diagnostics` 只允许映像位于本产品安装目录下的界面程序调用，和 `read_audit`、`read_selfcheck` 同一条核验；安装目录之外的程序只能发 `status` 与 `subscribe`。它不进连接指令的串行队列：连接指令卡住时也能导出；多条 `read_diagnostics` 之间自己排队。

## 测试包与正式包

- 测试包（`-TestBuild` 打出的包）把连接内核的日志换成 `{"disabled": false, "level": "warn", "timestamp": true}`，并在 `test_build` 段标出来。
- 测试包另在内核配置里加 `experimental.clash_api`：只听本机回环口 `127.0.0.1`，端口每次起内核时现取，口令每次随机，不写进日志与诊断；正式包不加，导出里也没有上面六个键。
- 正式包不碰内核配置里的 `log` 段，交给内核的配置与改动前完全一样（`disabled=true`）。

## 后台服务没连上时

界面拿不到 `service`，文件里只有 `ui` 与 `exported_at`，`service` 为 null，`service_error` 写明原因；后台服务还在但不认识 `read_diagnostics` 时，顶层 `firewall_audit` 与 `self_check` 是退回的两段内容。文件照样写出，不会因为后台服务没响应而不落盘。

## 真机待验证（本单未执行）

- 真机点「导出诊断…」，桌面出现文件，页面显示「已导出：」加路径，文件里 `service` 段有本机防火墙、过滤层、路由与 DNS 现状，日志末尾非空。
- 真机连不上澳洲出口时导出，`network` 段能看到默认路由、回环兜底路由（`0.0.0.0/1` 与 `128.0.0.0/1`，跃点 `9473`）与隧道路由是否在、DNS 指向哪里、连接内核进程在不在。
- 真机测试包连接后，`sing-box.log` 有 `warn` 级行，导出里主机名显示为 `[域名]`；正式包导出的内核配置仍是 `disabled=true`。
- 真机断开后台服务后导出，文件只有界面信息并写明 `service_error`。
- 真机跑 `read_diagnostics` 的 45 秒上限、超限裁剪与 1 MiB 管道上限各核对一次。
- 测试包连上后导出，`channels.selected` 与真实走的通道一致。
- `node_reach` 在线路正常的机器上是 `tcp` 为 `ok`、`tls` 为 `ok`。
- 连接期间 `ipv6_reach` 的读数。
- 后台服务以系统账户运行时 `security_products` 读得到。
