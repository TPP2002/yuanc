# 澳洲出口连接设置说明

这套工具负责准备连接设置和设备通行凭据。电脑或手机拿到自己的设置后，通过加密连接访问澳洲出口。它本身不是可点击安装的客户端，也不会替用户修改路由器。

## 两条连接通道

| 项目 | 默认设置 | 使用说明 |
| --- | --- | --- |
| 主通道 | VLESS + Reality，TCP 443 | 通常用于连接澳洲节点。 |
| 备用通道 | Hysteria2，UDP 24443 | 端口可以调整；节点和客户端必须使用相同端口。 |
| 自动选择 | 每分钟探测一次两条通道 | 根据可用性和探测结果选择，不保证主通道永远优先。 |
| 伪装目标 | www.microsoft.com，目标端口 443 | 可以由维护人员改为合适的澳洲本地站点；客户端的伪装名称与节点设置要匹配。 |

端口可以理解为节点接收连接的入口。路由器、防火墙和公网可达性需要由安装维护流程配置，本工具只生成设置，不自动开放端口。备用通道还需要维护人员提供证书和对应私钥；使用自签证书时，客户端必须明确配置所信任的证书，不能关闭证书校验来解决连接问题。

## 连接地址从哪里来

客户端连接地址由鉴权服务器下发，必须是 IPv4 数字地址，例如四段数字组成的地址。主通道、备用通道和手机分享链接都使用这个地址。

节点自己的动态域名供服务器和维护人员使用，不作为客户端的连接地址。把域名填入连接地址会被拒绝，并提示“连接地址必须是 IPv4 数字地址,由鉴权服务器下发”。这样首次连接不用先通过尚未接通的通道查找节点地址。节点地址变化后的刷新由鉴权服务器与节点心跳负责，本工具不自行查询或猜测新地址。

伪装目标名称与连接地址是不同的设置：前者用于主通道的握手，后者决定实际连接哪台节点。备用通道的证书名称单独配置，必须与其证书一致。

## 为什么连接断了就不能上网

连接期间，电脑的流量交给虚拟网卡处理。配置只在两条加密通道之间选择，没有“失败后改走本地宽带”的直连出口。两条都不可用时，请求会失败，不会用原网络偷偷继续访问。

查找网站地址的请求也必须经过加密通道，不配置本地备用解析服务。IPv6 流量被接入虚拟网卡后阻断，防止它绕过指定出口；当前可转发的业务流量使用 IPv4。

**这份配置不替代完整客户端的断网保护。** 如果连接程序本身退出，Windows 客户端还必须通过其防火墙保护维持阻断；用户主动断开后的网络恢复，也由客户端负责。手机应按配套应用的说明启用系统提供的持续连接和阻止绕行设置。配置文件存在、格式正确，并不等于已经在真实设备上验证过不泄漏；最终仍需断线和抓包验收。

## 每台设备有自己的通行凭据

每台设备分别登记账户、设备标识、平台、名称、创建时间和吊销时间，并拥有独立的主通道标识及备用通道密码。重复添加同一设备会复用已有记录，不会不断生成新凭据。已经吊销的设备不会因为重复添加就自动恢复使用。

节点以鉴权服务器给出的放行名单为准。名单中移除的设备会留下带吊销时间的记录，便于追查，不直接删除历史行。名单明确重新授权时才能恢复。更换主通道标识时，旧记录保留为已吊销，新记录用于连接。

首次生成的节点密钥会保存并复用；已有密钥文件损坏时会报错，不悄悄重新生成。请让维护人员处理，不要靠删除凭据文件尝试修复。

## 更新失败时会怎样

新名单先生成一份临时配置，交给连接内核检查。检查失败时，线上配置和设备登记表保持原样，也不会触发服务重载。检查通过后才更新文件并请求服务重载；重载失败时只尝试一次重启，仍失败则明确报错。

因此，“名单文件已更新”不等于“运行中的服务已生效”。如果收到重载或重启失败提示，维护人员必须核实服务状态。每 60 秒内同步并让吊销生效的调度、失败告警及实际连接核验，由调用本工具的节点服务负责。

## 保存、分享与日志

所有真实凭据和含凭据的配置只能保存到 `secrets` 目录。工具写入文件时使用 `0600` 权限，即仅文件所有者可读写；Windows 的同名权限调用不能替代账户访问控制，安装程序仍需设置合适的目录访问权限。

客户端配置和分享链接也含设备凭据，不要公开粘贴、发到群里或放进代码仓库。安卓可以使用完整的 sing-box 配置导入；单独的 `vless://` 分享链接只包含主通道，不包含备用通道、全局路由和完整断网保护设置。

生成配置关闭连接内核的访问日志。本包的状态日志不输出真实设备凭据；校验和服务命令的原始输出也不会直接写入日志。测试样例明确标记“测试向量,不是真凭据”，只能用于检查，不能用于实际部署。

## 给接入维护人员的补充

- 节点部署前必须安装 Reality 密钥对生成所需的第三方依赖 `cryptography`；Debian 12 使用 apt 包 `python3-cryptography`，开发环境依赖在 `requirements-dev.txt` 中声明为 `cryptography>=42`。
- 输入结构见 `ProxyContext`：`server_host` 是连接 IPv4 地址，`sni` 和 `handshake_server` 分别指定主通道握手名称和目标；备用通道证书使用独立字段配置。
- `sync_allowed` 仅更新登记表，不操作运行中的服务；正式发布使用 `apply_sync`，避免绕过配置检查。差集的 `added`、`removed` 返回 UUID 列表，`unchanged` 统计仍在放行名单中的 UUID 数量；密码更新也会写入记录。
- 同一登记表与线上配置必须串行更新。注入的 Runner 需保证 `write_file` 先设置权限，再原子替换单个文件。本包提供本地实现和内存测试实现；登记表与配置两个文件不构成跨文件断电事务。
- 校验临时文件位于线上配置旁的 `secrets` 目录，结束后清空其中凭据。调用者保存导出的配置或分享链接时也必须遵守相同的目录和权限要求。
- 配置按工单指定的 sing-box 1.10 格式编写；升级内核时需要重新校验，不能假定所有后续版本都接受旧字段。字段核对依据：[官方 1.10.7 TUN 文档](https://raw.githubusercontent.com/SagerNet/sing-box/v1.10.7/docs/configuration/inbound/tun.md)、[DNS 文档](https://raw.githubusercontent.com/SagerNet/sing-box/v1.10.7/docs/configuration/dns/server.md)、[自动选择文档](https://raw.githubusercontent.com/SagerNet/sing-box/v1.10.7/docs/configuration/outbound/urltest.md)。
- 本单仅完成配置生成与同步接口。自动化验收由派单器交活后执行；真实网络、客户端防火墙、服务部署及吊销生效时间需在集成阶段验证，不以静态自查代替。
