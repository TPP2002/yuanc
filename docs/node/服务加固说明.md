# 节点服务加固说明

> 任务:SEC-NODE-SYSTEMD-HARDEN-1022(对抗审查 A5、A13)。本文记录节点五个服务单元的降权与沙箱、凭据文件权限、防火墙规则表开机加载,以及真机待验证清单。本机只做了模拟测试,**真机未实测的项一律不标通过**。

## 为什么要做

加固前五个单元(隧道、托管、看门狗、更新收尾、救援)都没有 `User=`,只有 `NoNewPrivileges` 与 `UMask`。sing-box 以 root 监听公网 443/24443,协议栈任一漏洞即整机沦陷,Reality 私钥与全部设备凭据随之泄漏。防火墙规则表只在 `init` 时加载一次,重启即消失,首行注释还写着与实际不符的“管理入口限配置的监听地址”。

## 服务账户 exitnode

- **来历**:`exitnode init` 在“凭据目录”之后的“创建服务账户”步骤里先查 `getent passwd exitnode`,不存在才执行 `useradd --system --no-create-home --home-dir /nonexistent --shell /usr/sbin/nologin --user-group exitnode`。这是系统账户,没有家目录、不能登录,同名属组 `exitnode` 一并创建。已存在就复用,不重复创建。
- **用途**:只给隧道服务 `exitnode-proxy.service` 用,靠属组读取线上配置与备用通道证书对。
- **撤回**:安装清单登记撤回类型 `{"kind": "user", "name": "exitnode"}`,只允许这一个名字(清单里被改成别的名字会拒绝加载,不会删别人的账户)。`rollback`/`uninstall` 时在删除服务单元之后执行 `userdel exitnode`,账户已不存在也算成功。凭据目录按原规矩保留,账户删除后这些文件的属组会显示为数字编号。卸载后重新 `init` 时安装清单已清空,“创建服务账户”与“设置凭据文件权限”两步都会重跑,属组随之改回新建的 `exitnode`。

## 五个服务的加固项

### exitnode-proxy.service(隧道服务,系统账户 exitnode)

| 项 | 取值 | 作用 |
|---|---|---|
| `User=` / `Group=` | `exitnode` | 不再以 root 运行 |
| `AmbientCapabilities=` | `CAP_NET_BIND_SERVICE` | 只保留绑定 1024 以下端口(443)的能力 |
| `CapabilityBoundingSet=` | `CAP_NET_BIND_SERVICE` | 能力上限同上,其余能力一律拿不到 |
| `NoNewPrivileges=` | `true` | 不能借 setuid 程序提权 |
| `UMask=` | `0077` | 新建文件只本账户可读写 |
| `ProtectSystem=` | `strict` | 整个文件系统只读 |
| `ReadOnlyPaths=` | `/var/lib/exitnode/secrets` | 凭据目录明确只读 |
| `ProtectHome=` / `PrivateTmp=` / `PrivateDevices=` | `true` | 看不到家目录、独立临时目录、没有硬件设备 |
| `ProtectKernelTunables/Modules/Logs=`、`ProtectControlGroups=`、`ProtectClock=`、`ProtectHostname=` | `true` | 不能改内核参数、装模块、读内核日志、改控制组、改时钟与主机名 |
| `ProtectProc=` | `invisible` | 看不到别的账户的进程 |
| `RestrictAddressFamilies=` | `AF_INET AF_INET6 AF_UNIX AF_NETLINK` | 只能用网络、本地套接字与路由查询 |
| `RestrictNamespaces=`、`RestrictRealtime=`、`RestrictSUIDSGID=`、`LockPersonality=` | `true` | 不能建命名空间、抢实时调度、建 setuid 文件、改执行模式 |
| `SystemCallArchitectures=` | `native` | 只允许本机架构的系统调用 |
| `SystemCallFilter=` | `@system-service` | 只放行常规服务用的系统调用 |
| `After=` | `network-online.target exitnode-nft.service` | 防火墙规则表加载之后再起 |

**为什么只留 `CAP_NET_BIND_SERVICE`**:sing-box 服务端只需要监听 443(低端口)和 24443、读三份文件(线上配置、备用通道证书与私钥);日志关闭、没有缓存文件,不需要写任何地方,也不需要改路由、改防火墙或管理其他进程。所以只留“绑定低端口”这一项能力,其余一概不给。即使 sing-box 被攻破,攻击者拿到的是一个只读、无特权、看不到 Reality 私钥以外凭据(`reality.json`、`devices.json`、`hy2.obfs` 仍是 0600 root)的账户。注意线上配置本身含 Reality 私钥与设备凭据,这是 sing-box 运行必须读的,降权挡不住“读线上配置”,挡的是提权、横向移动与篡改系统。

### exitnode-admin.service(客户端包托管服务,动态账户)

| 项 | 取值 | 作用 |
|---|---|---|
| `ExecStart=` | `/usr/bin/python3 -P -m exitnode … admin serve` | `-P` 不把当前目录放进模块搜索路径 |
| `DynamicUser=` | `true` | 每次启动临时分配无名账户,停止回收 |
| `CapabilityBoundingSet=` | (空) | 去掉全部特权能力 |
| `IPAddressDeny=` / `IPAddressAllow=` | `any` / `localhost` | 内核层面只收本机连接 |
| `ReadOnlyPaths=` | `-/var/lib/exitnode/winclient` | 发布目录只读;前缀 - 表示目录不存在时跳过,首次发布客户端包之前托管服务也能正常启动,目录存在后只读 |
| `RestrictAddressFamilies=` | `AF_INET AF_INET6` | 只能用网络套接字 |
| `ProtectSystem=strict` 及其余沙箱项 | 同隧道服务 | — |
| `TasksMax=64`、`LimitNOFILE=1024`、`MemoryMax=256M`、启动频率限制 | 保留 | 资源兜底 |

**为什么用 DynamicUser 并只收本机**:托管服务只读 `/etc/exitnode/config.toml` 与 `/var/lib/exitnode/winclient/releases/`(0755/0644),日志走标准错误进 journal,不写数据目录,用不上固定账户;动态账户读不到凭据目录(0710 root:exitnode,不在 exitnode 组里)。它的唯一合法来源是本机 sing-box 转发来的隧道请求,所以用 `IPAddressAllow=localhost` 在内核层面只放本机连接,不靠防火墙规则表。相应地,`init` 在任何写入之前校验:`admin.bind` 必须是回环地址、`admin.port` 不小于 1024(没有能力的账户绑不了低端口),不满足直接拒绝安装。

### exitnode-watchdog.service、exitnode-recover.service、exitnode-rescue.service(仍以 root 运行)

| 项 | 取值 |
|---|---|
| `ExecStart=` | python3 后加 `-P` |
| `ProtectSystem=` | `full`(`/usr`、`/boot`、`/etc` 只读;`/opt`、`/var/lib` 仍可写) |
| `ProtectHome=`、`PrivateTmp=` | `true` |
| `ProtectKernelModules=`、`ProtectKernelLogs=`、`ProtectControlGroups=` | `true` |
| `RestrictAddressFamilies=` | `AF_UNIX AF_INET AF_INET6 AF_NETLINK` |
| `RestrictNamespaces=`、`RestrictRealtime=`、`RestrictSUIDSGID=`、`LockPersonality=` | `true` |
| `SystemCallArchitectures=` | `native` |

**为什么仍是 root**:看门狗要重启隧道服务、把上次可用配置写回并改属主;更新收尾要写 `/opt/exitnode` 与 `/var/lib/exitnode`;救援要重装程序、切换当前版本、重启服务。这些都要 root 的 chown、kill 与 systemctl 权限,所以不设 `User=`、不收能力集(`CapabilityBoundingSet`),只加不妨碍这些动作的沙箱项。两个定时器不变。

### exitnode-nft.service(新增,防火墙规则表开机重新加载)

`Type=oneshot` + `RemainAfterExit=yes`,`ExecStart=/usr/sbin/nft -f /var/lib/exitnode/exitnode.nft`;`DefaultDependencies=no`、`After=local-fs.target`、`Before=network-pre.target exitnode-proxy.service`、`ConditionPathExists=/var/lib/exitnode/exitnode.nft`(文件不在就跳过,不报错);`WantedBy=multi-user.target`。`init` 用 `systemctl enable exitnode-nft.service` 启用(不加 `--now`,规则已由安装步骤加载)。

## 文件与目录权限

| 路径 | 权限 | 属主:属组 | 说明 |
|---|---|---|---|
| `/var/lib/exitnode` | 0711 | root:root | 其他账户只能穿越、不能列目录;隧道服务与托管服务都要穿过它 |
| `/var/lib/exitnode/secrets` | 0710 | root:exitnode | 隧道服务能穿越、不能列目录 |
| `secrets/sing-box.json`(线上配置) | 0640 | root:exitnode | 隧道服务读取 |
| `secrets/hy2.crt`、`secrets/hy2.key` | 0640 | root:exitnode | 隧道服务读取 |
| `secrets/reality.json`、`devices.json`、`hy2.obfs`、`sing-box.last-good.json` | 0600 | root:root | 只有管理员能读 |
| `/etc/exitnode/config.toml` | 0644 | root:root | 不含凭据;托管服务动态账户要读 |
| `/var/lib/exitnode/exitnode.nft` | 0600 | root:root | 防火墙规则表文件 |

`init` 在“渲染隧道配置”之后的“设置凭据文件权限”步骤统一设置上表(幂等);**老节点再跑一次 `init` 时这一步会把旧的 0600 修成新权限**。

**每条改写线上配置的路径都保持 0640 root:exitnode**:

- 发布(安装、设备增删、名单同步):校验副本以 0640 写入并立即改属主,校验通过后原子替换;登记表写失败回退旧配置时同样 0640 并改属主。上次可用副本仍 0600。
- 看门狗回滚:暂存文件 0640,校验通过后、替换之前改属主。
- 救援恢复:第一次校验用的副本仍 0600;线上暂存文件 0640,第二次校验通过后、替换之前改属主。

## 防火墙规则表

规则表 `table inet exitnode` 的过滤策略仍是**占位**:`policy accept`,只放行本项目端口,不限制其他流量;不加真正的限制规则。规则文件与开机加载机制如下:

1. 首行注释改为如实描述(占位、开机由 `exitnode-nft.service` 重新加载、管理入口只收本机连接由托管单元的 `IPAddressAllow` 保证,不靠本表),删掉误导的“管理入口限配置的监听地址”。
2. 规则写成文件 `/var/lib/exitnode/exitnode.nft`(先写 `.tmp` 再原子替换,0600),内容开头是 `table inet exitnode` 与 `delete table inet exitnode` 两行(先声明再删除,在 Debian 12 的 nft 1.0.6 上表不存在也不报错,重复加载不会累加规则),随后 `nft -f` 加载。开机由 `exitnode-nft.service` 重新加载同一个文件。撤回时删表并删文件。

### 出口连接 TTL 与客户端一致

客户端 Windows 的默认 TTL 为 128,节点 Linux 的默认值为 64。隧道服务替客户端向目标网站发起连接,目标网站看到的是节点发出的包。因此在自管表 `table inet exitnode` 的 `postrouting` 链之后增加 `output` 链,使用 `type filter hook output priority mangle; policy accept;`,只将服务账户自己发起的连接设为 128,目的是**与客户端系统的默认值一致**。

两条规则分别为 `meta skuid "exitnode" ct direction original ip ttl set 128` 与 `meta skuid "exitnode" ct direction original ip6 hoplimit set 128`。`meta skuid "exitnode"` 限定隧道服务账户,`ct direction original` 限定连接的发起方向,覆盖代理出口流量及该账户的域名解析;给客户端的应答、SSH、更新和鉴权等节点自身的其他流量不改。原有 `input`、`forward`、`postrouting` 三条链保持不变。

不用 `sysctl` 修改全局默认值:全局改动会把节点自身所有流量一起改,范围更大,且不会随本表撤回。这里不修改 `net.ipv4.ip_default_ttl` 或 `net.ipv6.conf.*.hop_limit`,不另建表;加载时整体重建自管表,撤回时随表删除这两条规则。服务账户在安装网络规则之前已创建,开机重新加载规则时也已存在。

## 真机待验证

以下各项本机未实测,不标通过:

1. sing-box 以 `exitnode` 账户启动并监听 443/24443:`systemctl show exitnode-proxy.service -p User` 为 `exitnode`,`ss -ltnup` 看到 443(TCP)与 24443(UDP)。`exitnode check` 的“服务加固”层通过。
2. `systemd-analyze security exitnode-proxy.service` 与 `exitnode-admin.service` 的分数,记录到验收文档。
3. 重启后 `nft list table inet exitnode` 存在,且 `systemctl show exitnode-nft.service -p ActiveEnterTimestamp` 早于 `exitnode-proxy.service`(在隧道服务之前加载)。
4. 托管服务以动态账户运行且能下发 `latest.json`:隧道内 GET `/winclient/latest.json` 成功;从非本机地址直连监听端口被拒。
5. 尚未发布任何客户端包、/var/lib/exitnode/winclient 不存在时重启节点,托管服务应正常启动(ReadOnlyPaths 带 - 前缀,目录不存在就跳过,不再因 226/NAMESPACE 起不来);发布一次客户端包后再重启,目录在托管服务里应为只读。
6. 救援恢复与看门狗回滚后,隧道服务重启仍能读配置(线上配置是 0640 root:exitnode)。
7. 老节点(凭据 0600、无 exitnode 账户)再跑 `init` 后:账户已创建,上表权限被修正,隧道服务正常运行。
8. `SystemCallFilter=@system-service` 若导致 sing-box 起不来(journal 出现 `SIGSYS` 或 “code=killed, status=31/SYS”):先 `journalctl -u exitnode-proxy.service -b` 确认,再用 `systemd-analyze syscall-filter` 查缺的调用组,通过 `systemctl edit exitnode-proxy.service` 写覆盖片段追加放行(例如再加一行 `SystemCallFilter=@<缺的组>`,多行是取并集),不要整行删掉过滤;放宽项记入验收文档并回填模板。
9. 更新器与救援重启隧道/托管服务(root 发起)不受降权影响。
10. 出口连接 TTL 与客户端一致,**尚未实测**:在节点出口网卡抓包,例如 `tcpdump -ni <网卡> -v 'src host <节点地址> and not src port 443 and not src port 24443'`,客户端经隧道访问网站时,节点发出的新连接 SYN 的 ttl 应为 128,而节点自己的 SSH / apt / 鉴权包仍为 64。另去掉端口排除条件或单独筛选源端口 443/24443,确认给客户端的应答仍为 64;IPv6 同理查看 hlim,服务账户发起的连接为 128,其他流量和应答仍为 64。
