# 节点客户端包托管

`exitnode-admin.service` 提供只读客户端包 HTTP 托管，数据目录是 `<node.data_dir>/winclient/releases/`。发布目录使用 0755，文件使用 0644。HTTP 不提供上传入口、目录列表或访问日志。

## 发布与查询

维护人员先在维护机生成并签名客户端包，将 exe、manifest.json 和 manifest.json.sig 复制到节点临时目录，然后执行：

```sh
exitnode winclient publish --exe /tmp/YuanC-Client-1.0.0.exe --manifest /tmp/YuanC-Client-1.0.0.manifest.json --signature /tmp/YuanC-Client-1.0.0.manifest.json.sig
exitnode winclient status
```

节点检查产品、版本、三件套文件名、实际大小和 SHA256，签名必须非空。节点不验签名，客户端用内置公钥验签。全部检查通过后先原子发布三件套，最后原子写 `latest.json`；索引只保存文件名，不包含文件系统路径。同版本同内容重复发布幂等，同版本内容不同拒绝覆盖。较旧版本须明确提供 `--allow-downgrade`；这不会解除客户端“不安装比当前更旧版本”的门槛。未发布时 status 显示“尚未托管客户端包”。

## 服务与检查

正式入口 `exitnode --config <配置> admin serve`，前台运行并支持 SIGTERM 优雅退出；旧单元中的 `--placeholder admin` 等价，旧 `--placeholder proxy` 保持不变。更新器已有的管理服务重启动作会重启此服务。维护人员在部署后启动或重启 `exitnode-admin.service`，不需要开放公网端口。

托管服务已降权运行(详见《服务加固说明》):

- **动态账户**:单元用 `DynamicUser=true`,每次启动由 systemd 临时分配一个无名账户,停止即回收;`CapabilityBoundingSet=` 为空,不保留任何特权能力。托管服务只读不写,用不上固定账户,也不该能读凭据目录。
- **只收本机连接**:`IPAddressDeny=any` 加 `IPAddressAllow=localhost`,内核层面只放回环地址的连接。隧道里访问 `198.18.255.1` 的请求由本机 sing-box 转发到回环监听地址,来源是本机,不受影响。
- **监听必须是回环地址、端口不小于 1024**:`init` 在任何写入之前检查 `admin.bind` 必须是回环地址、`admin.port` 不小于 1024,不满足直接拒绝安装。没有特权能力的动态账户绑不了 1024 以下的端口;非回环地址即使监听上了也会被 `IPAddressAllow=localhost` 挡掉,只会造成“看起来开着、实际连不上”的假象。
- **配置文件 0644**:动态账户要读 `/etc/exitnode/config.toml`,`init` 把它设为 0644。配置文件按设计不含任何凭据(凭据只在 `secrets` 目录),所以对本机其他账户可读不泄露凭据;不要把密钥写进配置文件。
- 日志走标准错误进 journal,不写数据目录;发布目录 `winclient/releases/` 为 0755、文件 0644,动态账户可读。

`exitnode check` 与 `check --json` 新增“客户端托管服务”层，对配置监听地址的 `/winclient/latest.json` 发 GET，超时三秒。200 或 404 都算服务存活，连不上或其他响应算失败。这是本机托管健康检查，不能替代真实隧道下载验收。

## 连接限制

托管服务跑在小内存软路由上，一个慢客户端或一批半开连接不能拖垮整机，因此对连接做了限制：

- **15 秒套接字超时**：每条连接读请求头或写响应卡住超过 15 秒，服务端即断开该连接，不影响其他连接；超时断开不记日志（没有可操作信息）。
- **并发上限 32**：同时处理的连接最多 32 条。超限的新连接直接关闭，不开线程、不写任何响应字节；有连接结束后槽位自动归还。
- **监听队列 64**：内核等待接入的连接队列长度为 64。
- **单元资源上限**：`exitnode-admin.service` 带 `TasksMax=64`（最多 64 个任务/线程）、`LimitNOFILE=1024`（最多打开 1024 个文件描述符）、`MemoryMax=256M`（内存上限 256 MB）。服务自身的并发上限 32 低于这些值，单元上限是兜底：即使服务代码出问题，也只拖垮本服务，不拖垮整机。

超时与并发上限只作用于托管服务本身，不改协议路径与响应头，`exitnode check` 的探测逻辑不变。

真机待验证（本机未实测，不标通过）：

- 大量半开连接（约 1100 条只连不发请求）与每秒 1 字节的慢读期间，`exitnode check` 的“客户端托管服务”层仍通过，正常客户端仍能下载客户端包。
- 单元资源上限在 Debian 真机上实际生效，服务被限制时能由 systemd 按重启策略拉起。

## 安全边界

监听地址和端口只取自 `[admin]`，部署使用 `127.0.0.1:8443` 等回环配置。节点路由把隧道中的 `198.18.255.1/32` 送往本机监听端口；客户端现有 final=proxy 不变，因此更新源只在隧道内可达。不要改成公网监听；不新增公网防火墙规则。

“只收本机连接”由单元的 `IPAddressDeny=any` 与 `IPAddressAllow=localhost` 保证,不靠防火墙规则表(规则表是占位,`policy accept`)。监听地址必须是回环地址、端口不小于 1024,`init` 会拒绝其他取值;服务以 `DynamicUser=true` 动态账户运行、没有任何特权能力,即使托管服务被攻破也读不到凭据目录、改不了系统文件。配置文件 `/etc/exitnode/config.toml` 为 0644,理由是它不含凭据、动态账户需要读取。

仅 GET/HEAD，路径仅 `/winclient/latest.json` 与合法版本对应的三件套名称。拒绝 `..`、反斜杠、非法名及符号链接，不列目录。响应有 Content-Length、Content-Type、Cache-Control: no-store、Accept-Ranges: bytes。只支持单段 `Range: bytes=N-`，有效为 206，越界为 416。

启动和错误日志经 redact，不记录请求路径、客户端地址或异常原文。HTTP 不使用额外鉴权或 TLS，传输依托现有加密隧道，程序完整性依托客户端签名验收。Debian 单元、权限、信号退出及真实隧道/公网边界仍在真机待验证清单内。
